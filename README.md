# 万象跑团（Project DND）

> GitHub 源码副本：不含本地配置和游戏数据库。首次配置请先阅读 [GitHub上传说明](GitHub上传说明.md)。

公屏公开掷骰复用命运骰盘的 3D 骰型与落地动效，结果短暂保留后淡出。见 [动画与实际验证](docs/public-dice-shared-animation-2026-10-14.md)。

多人 TRPG 数字桌面。每位玩家使用独立账号；GM 管理房间、角色、地图和模板。人物卡可以按房间定义字段和公式，装备、特性与 Buff 的被动数值修正会重算并显示来源。战斗由参与者手动裁决：掷骰、动作声明和轮次推进不会自动扣血或消耗行动点。

战斗窗口选择有效关联目标后，服务器先生成临时 D20 对抗，所有有权限的成员在主视窗看到同一组骰点；保存复用本次结果，原成功广播与详情保留。旁边“判定”可选敏捷、力量、体质、智力、感知、魅力，行动方所选属性沿用敏捷加值表，对抗目标敏捷；比较「MAX(1, 属性加值 + D20)」，相等时闪避。记录类型为动作声明、结果裁定、GM裁定、自由备注；伤害和资源继续手动调整。见[两阶段判定与同步](docs/combat-drafts-2026-10-17.md)。

## 本地启动

Windows 日常使用可直接双击根目录 [启动跑团.bat](启动跑团.bat)：检查 Node.js 24 和指定 pnpm，缺少时下载到项目内，自动补装／修复依赖、启动原本地数据库、应用已有迁移，打开 **5242** 网页。保持启动窗口打开；保存后点右上角 **X**，本次启动的服务一起停止，数据保留。须保留 `apps/api/.env` 和原数据库；首次下载需要网络。原本已运行的数据库会保留，端口占用不会误关其他进程。

```powershell
pnpm --filter @dnd/shared build
pnpm --filter @dnd/api prisma migrate deploy
pnpm --filter @dnd/api prisma generate

```

## 当前工作方式

战斗窗口“记录一次行动或裁定”选择有效关联目标后，会由服务器生成一次临时敏捷对抗，主视窗同步显示双方头像、D20、敏捷加值与总值。动画结束保留安静的结果卡；改目标或行动角色会更新，选择“无”或关闭未保存窗口会撤下。保存记录复用这次判定，原保存结果广播和详情继续显示；属性/权限变化或判定过期时先重新确认，不在保存时悄悄补骰。私密角色、私密敏捷及“仅GM可见”沿用原范围。见[两阶段敏捷对抗说明](docs/combat-drafts-2026-10-17.md)。

背包默认24格。人物卡有数值型“力量”词条时，按当前有效力量（含装备/特性加成）计算：`24 + (力量 − 15) × 2`，最低0格、非整数结果向下取整；15点为24格、16点为26格、14点为22格。没有力量词条时沿用原容量。力量降低不会删除物品，超出格数的物品显示在“待整理”区域，可移入空格、穿戴或转移；占用达到容量时不能继续放入。GM与玩家实时同步，96格以上自动分页。

每位 GM 和玩家都可在房间左侧「设置」→「我在这个房间的名称」中保存自己的自定义名称，最多 30 个字符。名称只用于当前房间，其他成员会实时看到；留空保存或点击「使用账号名称」可恢复。登录仍用原账号，已有骰子、量尺和私密线索保留创建时的名称。

第一批界面反馈已加入：人物卡、角色摘要与悬停详情的生命/护盾显示短暂增减提示；浮窗区分当前窗口，并有关闭退场；常用保存与整理操作在窗口底部显示处理、完成或错误状态；背包和装备拖放提示具体目标、交换或不兼容状态，成功后短暂强调落位。沿用系统“减少动效”，首次进入及重连恢复数值不播放历史变化。

第二批界面反馈已加入：地图工具显示当前操作提示，单击棋子有本地选中环；四种量尺在放置前显示与实际尺寸、吸附一致的虚线预览，Esc 可取消。公开骰子与战斗结果自动纵向排布，避开回合提示；桌面最多保留两条尚未过期的近期摘要，窄屏收起摘要。单颗正向 D20 的天然 20/1 有轻量视觉提示，不改变判定规则。支持系统减少动效，本批按要求不修改私密线索。

私密线索通知现有一次约半秒的蜡封松开、信封轻启动效；继续使用原通知和未读角标，不自动打开或标为已读。每批新投递触发一次，刷新/回执不重复播放；正文区域保持原位，系统减少动效时显示静态信封。

浮窗和剧情观看窗已移除最小化，统一使用右上角叉号关闭；可从原侧栏/功能入口重新打开，剧情观看窗可从“剧情展示中”入口重开。原关闭保护及各模块既有草稿保存规则继续生效。

界面视觉层次已整理：普通输入、按钮及内容面板使用中性细线，古铜强调保留给窗口和主要操作。新旧人物卡统一档案式头像框、姓名层次、分组留白和等宽数值；生命/护盾使用独立色调，宽窗并列当前值与上限编辑卡，窄窗自动纵排，玩家上限隐藏规则继续沿用。

房间创建者可在大厅的房间卡片下方，或房间设置底部点击「删除房间」。确认后删除该房间及专属内容，在线成员返回大厅；普通玩家和其他房间的 GM 无此权限。见 [删除功能与验证记录](docs/room-deletion-2026-10-11.md)。

- **新房间**使用通用人物卡。GM 可新增数值、文本、布尔和选项字段，设置分组、顺序、可见范围及资源上限；字段 ID 与显示名分离。字段及其数值统一仅 GM 可修改，数值可手动设定或增减，变更有版本检查和日志。旧公式计算与既有字段约束保留。
- **公式**支持 `{{fieldId}}` 引用、四则运算、比较、`if/min/max/round/floor/ceil/abs`；循环、未知字段、除零和越界会报错。装备和模板支持加、乘、覆盖修正，卸下或停用后重算。
- **模板库**默认技能，筛选顺序为全部、技能、特性、特殊机制；含技能、特性和特殊机制，状态分类已从日常界面移除，历史状态及数值效果保留。共享安装随模板更新，独立副本保持原值；人物卡展示技能、可见状态与已安装特性，玩家窗口称为「能力」。模板说明不触发战斗行为。
- **人工战斗**可建立遭遇，GM 手动指定行动顺序、推进焦点，记录声明/结果/裁定/备注，追加更正并保留原记录；不再提供先攻机制。生命由 GM 修改，其他资源沿用字段权限。旧自动攻击历史可查看，`combat.attack` 新请求已停用。
- **自由骰子**由服务端生成随机值，支持 `NdM ± 修正`，包括任意 2–1000 面、最多 100 颗；公开结果同步全房间，玩家私密结果仅自己与 GM 可见，GM 私密结果仅 GM 可见。掷骰没有数值副作用。
- **协作**包括房间邀请码、角色归属、实时刷新、地图/Token、物品库、背包装备、玩家交易请求与接收方确认、任务与日志。公开任务支持 GM 私密备注。GM 可以隐藏地图、NPC 和 Token，配置装备部位，按自由/混合/受控模式及成员例外设置操作权限；物品资料由GM在物品库维护，背包只读展示，玩家不能改写实例资料或数量；既有实例差异和数值修正保留。图片上传经服务端解码并重编码，房间成员访问受控。
- **剧情图片放映**在房间左侧打开「导演台」。GM 可一次选择多张 JPEG/PNG/WebP 图片，编辑标题、说明、标签和仅 GM 可见备注；按章节整理图片，并创建可复用同一素材的 Cue。私下预览后点击「放映」，所有在线玩家的观看窗会同步显示；切换、黑幕、恢复、结束都会同步。断线或晚加入时会读取当前放映状态。Cue 可选择转场、沉浸模式建议及是否允许玩家事后回看。GM 可打开独立只读大屏页用于投影。
- **观看体验**中，玩家可以移动、缩放或关闭个人观看窗，选择减少动效；这些偏好保存在自己的浏览器中。沉浸模式建议不会强制覆盖个人退出选择。「线索」仅列出 GM 已公开且允许回看的图片，GM 私密备注不会显示。
- **界面动效**用于浮窗与提示入场、按钮反馈、资源条变化和 3D 掷骰。骰盘支持常用多面骰造型、翻滚、落桌弹跳与阴影；点数取自服务器结果。已打开骰盘的成员会展示新收到的可见结果，私密权限保持原样。动效可单独关闭，系统选择“减少动效”时关闭全站动效。详见 [3D 骰盘说明与验证](docs/dice-animation.md)。
- **角色状态与 GM 备忘**支持自定义图标/emoji、颜色、角色独立长备注、三种可见范围、状态库可恢复删除、批量分配与检索总览。人物卡、角色目录与地图显示可见徽章；保存后多人同步，刷新恢复。技能自定义词条仅记录；角色状态同名数值词条参与人物卡计算，可从技能复制为独立状态，默认全房间公开。胸部另有背包位，“格数”增加背包容量。见[状态与背包说明](docs/states-backpacks-2026-10-17.md)。见 [使用说明](docs/character-tags-usage.md) 与 [实施状态](docs/character-tags-implementation-status.md)。
- **私密线索（v3.3）**：GM 把文字及最多 5 张图片只投递给选中账号；玩家通过非模态通知和私人收件箱查看，独立已读、收藏及回看，离线重连后恢复。支持 GM 发件箱、回执、受控分享和撤回；剧情图库可复制为私密附件，删除图库原图不影响已发线索。复用原数据库、窗口与图片卷，不新增服务。见 [使用说明](docs/private-clues-usage.md) 与 [阶段验证记录](docs/private-clues-implementation-status.md)。

本项目按 3–8 人熟人局使用：登录、注册和普通图片上传不设置额外的内存计数限流，避免集中登录或批量上传被误拦截。账号、房间与 GM 权限、图片格式和大小检查、重复操作保护及版本冲突提示仍保留，以免误公开内容或重复修改游戏数据。

大厅先加载基本界面；进入房间时加载地图，首次打开浮窗时才加载人物卡、战斗、物品等面板。在线状态变更只更新成员指示灯，房间数据变更与断线重连仍会重新读取快照。

旧房间继续读取原有六维、经验、血量、装备与公式数据，不会因迁移清空。新房间默认使用通用人物卡模式；旧数据的自动战斗事件保留历史标记。

## 开发验证

```powershell
pnpm typecheck
pnpm test
pnpm build
pnpm lint
pnpm format:check
pnpm e2e
pnpm --filter @dnd/api smoke:v3
pnpm --filter @dnd/api smoke:presentation
```

两个冒烟脚本要求已启动 API 和 PostgreSQL，并存在上述示例账号；它们会创建和清理临时数据。`smoke:presentation` 覆盖上传、章节、Cue、放映操作、版本冲突、权限和图片缺失。`pnpm e2e` 使用独立 Edge 浏览器上下文，需要本机安装 Edge、运行中的 PostgreSQL 和示例账号；Playwright 可自动启动 API/Web。详细实测状态与剩余风险见 [v3.0 实施状态](docs/implementation-status.md)和 [v3.1 图片放映状态](docs/presentation-implementation-status.md)。

## Windows Server 正式运行

直接双击 `启动跑团.bat`：默认正式模式，首次/源码变化时构建，未变化时复用构建；网页资源预先生成 Brotli/gzip 并使用缓存。默认 Node 堆上限 4096MB、后台线程 8、每个图片任务 2 个处理线程及 128MB 图片缓存。配置在 `apps/api/.env`，端口及公网转发保持 5242。开发时可使用 `启动跑团.bat -Development` 或 `pnpm dev`。完整步骤和参数见 [Windows Server 部署说明](docs/windows-server-deployment.md)。

## 已知待办

地图／人物卡／Token 的任意指定玩家可见范围、旧人物卡向新字段的交互式迁移和其他浏览器验证仍未完成；v3.3 私密线索已独立支持指定接收账号。本机测试不能代替实际 Windows Server 的异地网络与长期负载验证。产品边界见 [v3.0 决策](docs/product-decisions.md)，代码结构见 [架构说明](ARCHITECTURE.md)。

本地BAT数据库启动使用项目内固定运行环境（`.launcher/runtime/database`），校验核心文件后复用原库，不再依赖每天变化的临时CLI缓存。失败详情保存在`.launcher/database-startup.log`，强制关窗后的锁会限时自动恢复。见[启动修复说明](docs/database-startup-fix-2026-10-18.md)。

人物卡下方技能、状态、特性可悬停或键盘聚焦查看详情，长内容可滚动，保留原点击与启停操作。状态库使用“删除状态／恢复状态”，删除仅移出库的可分配列表，人物卡已有状态保留。见[能力详情说明](docs/ability-details-2026-10-18.md)。

可选「回合与时序系统」：GM 侧栏配置多属性先手模板，人物卡可单独覆盖并查看贡献；从当前地图选择人物后，全员显示权限过滤的头像顺序和轮数，GM 结束回合只扣减当前人物的有限状态，到期实际解除并撤销修正。支持暂停、人工改序、中途增减与轮数延长；原 D20 裁决与成功弹窗保留。见[使用、算法、迁移与实测说明](docs/turn-system-2026-10-18.md)。

状态编辑支持「无、I–X」罗马数字后缀，金色古典字体显示于名称后，并同步人物卡状态栏及详情。状态库可设默认值，人物状态可独立修改；仅作展示，不改变加成或剩余回合。见[状态数字说明](docs/state-roman-2026-10-18.md)。

回合顺序按轮锁定：轮末状态到期和有效属性更新完成后，服务器原子重算下一轮并直接选中新首位。中途手动重算保留当前行动者及已行动标记，同分保留已有顺序。见[动态重排与验证说明](docs/turn-round-rebuild-2026-10-18.md)。
