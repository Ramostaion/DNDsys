# 敏捷关联、双 D20 对抗与战斗结果广播

> 最新规则：MAX(1, 敏捷属性加值 + D20)。详见 [最终规则与验证](agility-final-contest-2026-10-14.md)，以下原实施证据保留。

> 后续规则已更新为「敏捷属性加值 + D20」。本文保留上一轮实施和测试原记录；当前规则与本轮验证见 [敏捷加值对抗更新](agility-bonus-contest-2026-10-14.md)。

日期：2026-10-14。基于现有人物字段、数值引擎、人工战斗记录及 Socket.IO 增量实现。

## 使用与触发

1. GM 在房间人物卡基础信息中添加唯一的数值词条「敏捷」，为玩家/NPC 设置基础值；原装备、饰品与生效状态/特性修正继续参与计算。
2. 打开战斗，进入「记录一次行动或裁定」，类型选择「动作声明」，选择声明角色及另一名关联目标。
3. 点击保存，服务器自动独立投双方 1D20。双方选择完整时，说明可以留空，服务器用真实角色名生成行动说明。
4. 窗口保留，并出现命中/闪避详情；在线房间成员的主视窗同步出现非模态广播，约 6 秒后消失。广播不捕获鼠标输入，人物卡编辑草稿保持。
5. 在时间线展开「查看判定详情」，读取当时的完整快照。

非动作声明继续只保存原记录。未选择声明角色/目标、目标为自己、缺少/重名/非法敏捷等情况保存普通行动说明，并显示未执行对抗的原因；没有伪造属性或骰子。

## 唯一判定规则

```
当前有效敏捷 = MAX(1, 统一数值引擎的敏捷最终值)
攻击方判定值 = 攻击方当前有效敏捷 + 攻击方 D20
防御方判定值 = 防御方当前有效敏捷 + 防御方 D20
攻击方 > 防御方：命中
攻击方 <= 防御方：闪避
```

敏捷属性加值按任务指定范围独立计算：7/8/9 为 −1，10–12 为 0，13–15 为 +1，16–18 为 +2，19–20 为 +3；超过 20 使用 `4 + floor((敏捷 - 21) / 2)`。没有额外上限。自然 1/20 不触发失败、成功或暴击。

加值只展示，不叠加到此次命中值。最低 1 只用于当前有效敏捷；原基础值、原始最终值和其他资源规则保留。人物卡显示当前有效敏捷及新标准加值；选择角色后自由骰可引用「当前有效敏捷」或「敏捷属性加值」。既有自定义同名字段的原值保留。

道具效果沿用原状态/数值修正机制生效，读取已经生效的修正；本轮没有新增道具使用或效果持续时间结算。生命、护盾、行动点、伤害、轮次与剧情继续由 GM/参与者人工裁决，旧 `combat.attack` 仍停用。

## 数值读取与事务

- 自定义卡通过唯一的显示名称「敏捷」关联字段 ID，读取原始值/合法默认值、统一引擎最终值及来源；旧卡读取真实 `attributes.敏捷`。旧引擎内部默认敏捷不会冒充缺失词条。
- 每次对抗都重新读取房间定义、角色、当前穿戴、特性和状态，调用原 `refreshCharacter` 重算；不会使用遭遇建立时的缓存，也不重复添加装备效果。
- 修正快照保留来源名称、类型、实例标识与净变化，支持原加法/乘法/覆盖效果。若历史公式导致基础到最终值间有额外差额，明确记录为公式/其它计算来源。
- `combat.record` 复用原房间行锁和 Read Committed 事务，先查操作收据；双方角色按 ID 排序加行锁，保证基础与重算结果处于同一稳定快照。一个事务保存行动、完整结果、操作收据与日志。
- 正式运行使用 Node `crypto.randomInt`，通过已有 `rollDice('1d20')` 解析器独立调用两次。两颗骰子属于一次战斗对抗，点数存入战斗记录；自由掷骰原接口、独立历史和 2 秒公开冷却保持。

## 记录、重试与广播

- 原 `CombatEvent.data.contest` 保存版本、操作编号、时间、双方 ID/角色名/玩家或 NPC 类型、基础敏捷、全部生效修正、原始最终值、当前有效值、属性加值、双方 D20、判定值、比较符号、原因、广播文本和状态。
- 后续修改基础敏捷、穿脱装备、改变状态、改名或更正裁定都不会覆盖已有判定。更正仍是追加记录。
- 前端用同步的进行中标记阻止重复保存；网络/5xx 失败时冻结原请求及操作编号，提供「重试保存上次记录」。服务器相同编号返回原结果，不重新投骰或广播。
- 复用原 Socket.IO `change` 中的 `combat.record`，仅增加已保存判定的摘要字段：`roomId`、`recordId`、`operationId`、`createdAt`、`serverNow`、`message`、`hit`、双方有效敏捷/D20/总值。
- 广播在事务提交后执行；前端按记录 ID 去重，最多保存 128 个标识，只接收当前房间实时通知，过期通知不演出。刷新、重连快照及历史展开不重播。
- 广播状态为 `PENDING` / `SENT` / `FAILED`。SENT 表示发送调用完成，**不表示已逐一确认所有浏览器收讫**；失败仍返回已保存结果。发送状态写入失败不把成功保存改为 HTTP 失败，历史可能保留待确认状态；不自动重发造成重复演出。
- 隐藏角色、GM 私密记录或私密敏捷由 GM 判定时保持 GM 范围；普通玩家对私密敏捷只保存普通声明。广播摘要不包含装备实例；记录展示复用原背包可见权限，没有查看权的装备来源显示为「装备修正（来源不可见）」，GM 保存/查看完整来源。
