# 架构解耦与 NAS 运行调整

> 本文保留 2026-10-11 的实施与测试证据。Docker/NAS 部署文件已于 2026-10-14 移除；当前使用 [Windows Server 正式运行](windows-server-deployment.md)。

实施日期：2026-10-11。基于当前 v3.3 及后续人物卡、装备、权限修复增量修改；未更换架构、数据库或已有图片目录，没有新增数据库迁移或服务。

## 检查发现

- API 入口混合账号、房间接口、联机、配置与启动；约 60 KB 的 operations 文件包含 60 种操作，改动容易影响无关业务。
- domain 同时负责结构兼容、人物重算和权限快照；前端 App 同时包含登录、大厅及房间，浮窗容器混合移动缩放、功能内容和设置。
- 生产模式强制 Secure Cookie，导致内网 HTTP 无法维持登录；健康检查只报告进程存活，没有实际读取数据库。
- API 容器通过 shell 启动，缺少统一停止流程；Nginx 默认上传限制低于应用图片上限，API 地址缓存影响容器替换后的连接。
- 本地生产包部署会复制源码、测试、本地 .env 和图片目录，发布内容没有明确边界。
- 多份源码压成很长的行，阅读、差异审查和局部维护困难。

## 阶段一：API 启动与基础边界

已完成。拆出 config、storage、auth、access、error-handler、realtime、app、bootstrap 和 routes；入口只负责读配置、启动及信号停止。

应用组装不自动连接或修改数据库，可注入数据库进行测试。启动仍执行旧背包整理和人物重算，保留原兼容行为。图片目录在启动时验证可写；端口、访问源和生产密钥有明确检查。Cookie 按访问源的 HTTP/HTTPS 设置。

健康检查区分 live 和实际数据库 readiness。关闭顺序为标记停止、关闭联机及 HTTP、等待已接收请求结束、断开数据库；重复关闭复用同一 Promise，入口设置 15 秒退出上限。

验证：新增四项配置／运行测试，纳入最终 69 项单元测试；配置、数据库健康故障／恢复、无启动副作用、存储写入和在途请求关闭顺序通过。此项等待测试为进程内测试，不代表已验证 Linux 容器 SIGTERM。

## 阶段二：业务操作与数据职责

已完成。operations 保留统一事务、操作去重、版本检查、日志、背包整理及提交后通知，处理器按角色／字段、地图、物品、背包／装备、交易、模板、任务、绘图拆分。60 个原操作 case 均保留，战斗和标签继续复用已有独立模块。

新增 context、dispatch 和业务 helpers；拆出 data、character-values、snapshot。domain 保留兼容导出，旧脚本仍可使用原入口。业务公开接口、事件名、事务边界及权限规则没有改变。

验证：先完成 6/6 定向联机，覆盖特性共享同步、双向背包装备取放、交易权限、地图编辑、自定义物品及 v3.0 公式／装备／历史 Buff／人工战斗／骰子。后续完整套件继续覆盖这些功能。

## 阶段三：前端页面、窗口与恢复

已完成。App 保留账号门禁与路由，登录、大厅、房间各自维护。Room 分离 useRoomSession、useRoomConnection，以及侧栏、同行者、绘图工具、设置组件。Windows 只管理浮窗交互，窗口内容路由、标题与设置另有模块。

房间连接按账号和房间维持单个 Socket，更新回调不重连；加入确认后才显示连接成功，加入失败和服务端断开有重试，重新加入会补读角色、放映和收件。原焦点、上线和定期补读机制继续保留。

完整回归发现后台账号校验临时失败会卸载房间。现修为：已有有效账号数据时继续保留房间与草稿、连接恢复处理；明确 401 仍清除账号并回到登录。新增 503 后台校验失败场景，随后离线／恢复可继续收取私密线索。

验证：初期 4 项回归为 2/4，两个旧标签选择器匹配到新技能区同名标签，改为精确匹配后在完整套件通过。最终全套及复测结果见下表。

## 阶段四：NAS 配置、发布与维护

已完成源码及配置修改；容器实机未验证。

- API 入口脚本先执行已有 migrate deploy，成功后 exec Node；Compose 配置 init、30 秒停止宽限、启动健康宽限、HOST 和 Web 健康检查。
- API 构建阶段安装 OpenSSL，与 Alpine 运行环境保持兼容。
- Nginx 动态解析 Docker DNS，API／图片／Socket 使用同一个后端，支持代理头与 WebSocket；上传限制 12 MiB，应用图片限制保留，页面入口与哈希资源分别缓存。
- compose.yaml 原命名卷不变；新增可选 compose.nas.yaml，供新安装使用可见目录。已有部署切换前需复制同一份数据库及图片，并检查权限。
- API 发布只包含 dist、prisma、入口脚本；共享包只发布 dist。原配置、图片、源码、测试不复制进发布包。
- 统一源码／联机测试格式，添加 format 和 format:check，不加入新的应用基础设施。
- 更新 ARCHITECTURE、README、玩法启动说明及 NAS 部署操作。总记录追加稳定编号，历史证据保留。

首轮完整联机三项失败：八账号标签选择器匹配重复标签；玩家权限旧测试仍期待生命上限；断网恢复时账号校验错误卸载房间。前两项按当前已确定的产品行为修正测试，第三项修复实际前端并加入回归。

联机复测后补齐停止状态的业务请求 503 拒绝检查，重跑全部 69 项单元、生产构建、代码与格式检查通过；这处停止分支通过运行单元测试验证，没有再重跑完整浏览器套件。

八账号复测本机观测：快照读取合计 459 ms；1920×1080 放映画面八端加载约 384 ms，屏幕文件 1,225,620 字节。这只是本机单场景结果，不是 NAS 性能保证。关闭浏览器时有 Vite 代理连接重置输出，未影响通过结果。

首次生产包检查发现本地文件被复制，收窄 files 后复验通过；包中 Prisma 客户端须按现有 Docker 步骤生成。验证期间 pnpm 对 deploy 的生产配置和测试环境配置切换曾触发非交互确认错误，恢复开发依赖配置后构建和检查通过，没有修改数据库地址或更换数据库。

本轮开始时用户服务均未监听。测试临时启动项目原 .local-database，并由测试启动 API／Web；测试账号及房间按用例清理。结束后临时服务关闭，原库和图片保留。日常使用继续双击启动跑团.bat。

本轮临时部署副本和官方配置校验工具的清理被自动审批拦截，只返回“blocked by policy”。核对为本项目 .launcher 下的三个目录，改用明确路径清理仍被拒绝，因此保留 deploy-api-architecture、deploy-api-architecture-clean 和 architecture-tools；它们被 Docker／发布包忽略，不影响运行。第一个部署副本是收窄发布范围前生成的本地测试副本，包含原 .env 和图片副本，不应单独作为发布目录。

## 尚未验证与后续边界

- 没有 Docker 引擎和群晖设备，镜像构建、Linux 停止信号、容器 IP 更换后的 DNS 恢复、真实 NAS 挂载 ACL、双卷备份恢复尚未实机验证。
- Firefox、Safari、手机触屏、真实异地网络和连续多日运行未实测；没有逐条人工核对全部历史数据。
- 未引入通用仓储层、微服务或消息队列。地图画布、导演台、私密线索等大型功能文件仍可按具体变更逐步拆分；现有图片模块使用同一进程配置，未改成完整依赖注入体系。
- 本轮没有修订既定游戏规则或实现此前明确未完成的高级功能。权限隔离、事务及重复操作保护继续保留。
