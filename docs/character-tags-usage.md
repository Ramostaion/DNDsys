# 角色标签与 GM 备忘（v3.2）

## 给角色添加标记

1. GM 打开人物卡，点击「管理角色标签」。角色目录也有同样入口；地图 Token 右键菜单可打开角色标签。
2. 点击「添加标签」，选择已有定义；或「新建定义并添加」，自由填写名称、选择图标/emoji、颜色及默认值。
3. 在同一浮窗填写「角色专属详细备注」，选择可见范围与优先级，点击「添加到此角色」。
4. 点击头像周围的图标查看完整详情。GM 可点「编辑此角色备注」，明确提交保存；玩家只能阅读有权查看的内容。

一个定义可以用于多个角色，但每条详情完全独立。定义里的「备注初稿」仅在分配时复制一次；之后修改初稿不改变历史备注。更新定义的名称、图标和颜色会更新所有引用它的徽章。

## 三种可见范围

| 范围 | 谁能看到图标、名称及详情 |
|---|---|
| 仅 GM 可见（默认） | 房间 GM |
| 角色控制者与 GM | GM、角色所属账号和获准编辑其他玩家角色的成员；NPC 此范围仅 GM 可见 |
| 全房间公开 | 能查看此角色的房间成员 |

隐藏角色仍遵守房间原有角色可见性。未授权标签不会下发给玩家，`+N` 只统计当前账号可见的标签。由公开改为私密后，其他玩家已打开的详情会更新为无权限提示。

## 长备注与保存

备注最多 100,000 字符，支持普通文本、换行、标题、粗体、斜体、列表、引用以及 HTTP/HTTPS 链接。HTML 按普通文字显示。点「预览备注」检查排版，再保存。

只有提交才保存和同步，不会每敲一个字广播。显示「保存成功」后数据才确认写入。保存失败时输入保留，可重试；另一个 GM 修改同一备注时，旧窗口会提示冲突，并提供「复制草稿」「重新加载」。重新加载会确认是否丢弃草稿。其他窗口移除标签时，GM 的编辑草稿仍可复制，但不能再保存到已移除实例。

浮窗关闭和浏览器刷新/关闭会保护未保存草稿；最小化不会丢弃。草稿不是离线数据库，长篇编辑请及时保存。连接恢复后自动读取最新已保存内容。

## 标签库、总览与批量分配

- 左侧「标签」打开 GM 标签库。可以检索名称、查看关联角色数、编辑定义、归档和恢复。
- 「角色标签总览」按角色、定义、可见范围和优先级筛选，搜索名称与详情全文；点击结果打开那条角色实例，可直接编辑或移除。
- 「批量分配」勾选多个角色，每个角色分别复制一份备注。已有同定义标签的角色跳过，原备注不会被覆盖。
- 优先级越大越靠前；最多显示 3 个头像图标，其余为 `+N`。点击 `+N` 打开完整可见列表。地图徽章使用同类符号，并保留 Token 拖动与原右键菜单。

「从此角色移除」会删除该角色的标签实例及备注，需确认；不会影响其他角色或定义。「归档定义」保留所有历史实例与备注，仅禁止新的分配。当前不提供永久删除整个定义的入口。

标签是叙事记录，不改变生命、行动点、装备、Buff、属性或战斗轮次，也不会执行备注中写下的触发条件。

## 升级与恢复

本功能复用原数据库、API 和 Socket.IO；标签和长备注保存在数据库，图标不上传图片。

本地升级（先备份现有数据库）：

```powershell
pnpm --filter @dnd/api exec prisma migrate deploy
pnpm --filter @dnd/api exec prisma generate
pnpm build
```

新增迁移是 `202610100001_character_tags`，仅新增表、索引及外键。不要使用 `migrate reset`。Windows BAT 启动会运行 migrate deploy；更新前同时备份原数据库、图片和配置，见 [Windows Server 部署说明](windows-server-deployment.md)。

实机恢复验收：在备份副本中分别给 A/B 写超过 2,000 字的不同私密备注，再公开一条；重启 Windows BAT，核对 GM、所属玩家与其他玩家的图标/详情，确认 A/B 内容完整且不同，再检查旧人物卡、装备、状态、地图与剧情放映。早期实施证据见 [实施状态](character-tags-implementation-status.md)。

复现检查：

```powershell
pnpm typecheck
pnpm test
pnpm build
pnpm lint
# 本地 API、数据库、示例账号就绪后
pnpm --filter @dnd/api smoke:tags E
pnpm exec playwright test apps/api/e2e/character-tags.spec.ts
pnpm e2e
```
