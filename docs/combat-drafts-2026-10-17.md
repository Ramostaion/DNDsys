# 关联目标实时敏捷对抗 · 2026-10-17

## 使用方式

在战斗窗口“记录一次行动或裁定”中选择行动角色与不同的有效关联目标后，等待服务器生成临时判定。所有有权观看的在线成员在主视窗看到同一结果：头像、名称、独立D20、所选属性加值和最终总值。判定下拉可选敏捷、力量、体质、智力、感知、魅力，行动方所选属性对抗目标敏捷，均复用原敏捷加值表。普通结果/裁定类型通过新界面关联目标时也使用该草稿；没有关联双方时继续保存原文字记录，GM专用类型的权限不变。

卡片采用深色半透明底、古金色与银蓝色双方。约320ms入场，约1.2秒完成数字演出；随后保留低对比静态结果，停止数字、粒子和发光演出。换目标或行动角色以新事件替换，选择“无”约240ms淡出；关闭未保存战斗窗口也撤下。浮层不接收鼠标，不修改地图/Token/血量/资源。支持系统减少动效。

“保存记录”复用本次判定，成功后临时卡片撤下、目标重置为无，原 `CombatResultBanner` 与窗口内 `AgilityResult` 正常显示。请求失败沿用原错误和重试流程，不伪造保存成功。敏捷、装备效果、角色范围或控制权限变化时，旧临时结果失效；等待新判定后再保存。

## 权威数据和兼容

- `CombatDraft` 按草稿ID关联房间、发起账号、双方、范围、版本、事件ID、输入指纹、临时结果、租约和结束状态；新迁移 `202610170002_combat_drafts` 不修改旧表/记录。
- 服务器复用 `characterDerived`、`characterAttribute`（原`characterAgility`包装保留）、`adjudicateAgility`：重新读取角色、装备、特性、公式与房间规则，独立产生两颗真实D20。前端数字翻动使用固定装饰序列，最终点数、加值与胜负仅来自服务器。
- 规则不变：先把有效敏捷限制为至少1，再用现有区间取得加值，`MAX(1, D20 + 加值)` 为最终判定；攻击方严格大于防御方才命中，相等时闪避。
- 原 `combat.record` 继续拥有正式事务、房间锁、操作回执、权限及历史。新界面提交 `draftId/draftRevision/draftEventId`，服务端验证当前所有者、双方、范围、版本、租约和最新指纹后复制原判定；保存分支不调用投骰函数。
- 成功保存将草稿标为SAVED、清空临时判定及指纹并关联正式记录；重试相同操作ID取得原收据。另一操作ID不能再次消费SAVED草稿。保存前后不会产生两套相互矛盾的Dice或结果。
- 无草稿引用的旧API动作声明继续原来的单阶段判定；旧的普通备注/结果API仍不自动掷骰。新界面选择关联双方后统一走两阶段流程，GM专用裁定权限继续检查。
- 临时判定不创建战斗事件、自由骰历史、活动日志或正式操作回执。取消清空结果并保留版本/终止标记，防止晚到HTTP请求复活旧演出。

## 同步与失效

| 接口/消息 | 行为 |
| --- | --- |
| `PUT /api/rooms/:roomId/combat-drafts/:draftId` | 提交递增revision、actorId、targetId、privateRecord、actorAttribute（默认敏捷）；有效输入生成或复用判定，空双方取消 |
| `DELETE /api/rooms/:roomId/combat-drafts/:draftId` | 终止窗口草稿；无既有行时也创建终止标记，拦截晚到创建 |
| `GET /api/rooms/:roomId/combat-drafts` | no-store；只返回当前账号可看、输入指纹仍匹配且租约有效的临时结果 |
| `combatDraft.changed` | 原Socket连接上的独立通知，仅含roomId；各端重新读取过滤后的列表，不发送私人内容或刷新整张地图 |
| `combat.record` 草稿引用 | 验证并消费同一判定；过期/错配/已结束返回409，权限冲突返回403，不隐式补骰 |

同一房间的预判、取消和正式保存复用房间行锁；角色行按稳定ID顺序锁定。每次保存重算最新输入，包含实际敏捷及来源，即使17→18仍处于相同加值区间也会失效。不同房间/发起人不能通过相同ID改绑他人草稿；创建和更新明确分开，唯一键碰撞只产生冲突。

每个战斗窗口使用独立草稿ID，修订号递增，事件ID识别一组真正的新判定。HTTP迟到响应由请求序号丢弃，观看端也丢弃迟到列表；发起端在新请求完成前遮蔽旧事件，避免旧目标短暂出现在新卡上。多个发起人同时操作时按草稿分别展示。

租约90秒，活动发起窗口每25秒续期；输入未变化时复用原事件和骰点，不重复播放。观看端每15秒补拉、按服务器时间到期。正常关闭用keepalive DELETE；网络中断或浏览器崩溃无法发送撤回时由租约兜底。相同修订号的过期续期被拒绝，必须重新选择或手动重试，重连不偷偷生成新骰点。数据库保留终止标记防止重放；过期未清理的行不进入展示或历史。

## 权限

发起人必须仍是房间成员，并能控制行动角色；玩家不能操作隐藏NPC或私密角色，GM专用记录类型和私密选项继续仅GM可用。公开敏捷和公开双方的结果面向房间；私密记录、隐藏角色或私密敏捷按原规则只向GM展示，玩家缺少公开合法敏捷时不生成公共对抗。

通知不包含头像、角色ID、名称、Dice、行动正文或结果。HTTP输出只有可见双方的摘要，不输出装备来源、原始属性、未保存正文或其他账号草稿凭证。每次读取都检查当前控制/隐藏/字段范围与指纹；撤权或隐藏后旧结果不会继续从接口发出。原保存广播与历史权限逻辑保留。

## 刷新压力修复（同日晚间）

GET改为只读批量查询，不进入交互事务；同一请求内缓存相同角色/属性计算。地图移动、画笔和量尺事件不再通知对抗读取；观看端刷新在途合并。写事务等待上限15秒、执行上限10秒；事务繁忙返回503和重试提示，不伪造保存成功。actorAttribute保存在临时adjudication元数据中并参与指纹、同版本冲突和正式保存核验，不新增数据库列。
