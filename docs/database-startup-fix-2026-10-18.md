# BAT 卡在启动数据库 · 2026-10-18

## 原因

实际复现原命令后，今天的 `prisma dev` 临时运行缓存中缺少 `@electric-sql/pglite/dist/pglite.wasm`，数据库进程直接以ENOENT退出。原启动器将输出丢弃后反复重启，界面仅停在“正在启动已有本地数据库”。昨天的完整缓存与今天的不完整缓存版本相同，数据目录及数据库连接设置正常。

## 修改

- 增加项目专用数据库运行目录 `.launcher/runtime/database`。固定使用已验证的 `@prisma/dev@0.25.2` 和 `@electric-sql/pglite@0.4.3`，不再每天通过`prisma dev`选择新的临时CLI缓存。
- 启动前检查版本、PGlite三个核心文件及Prisma运行资源清单。优先复用本项目完整环境，其次从完整的已有缓存复制；没有可用缓存时才安装固定版本。损坏的项目环境改名保留后重新准备，不清理游戏数据库。
- 新入口显式使用stateful模式，并先确认原登记及PG_VERSION存在；不会创建新的空库替代原库。保留原端口、数据路径、路径修复、数据库健康检查与原启动器进程管理。
- 输出保存在 `.launcher/database-startup.log`，失败时展示末尾错误并记录诊断路径。一般错误最多重试两次；强制关闭后出现ELOCKED时，允许在原60秒期限内等待辅助服务的30秒过期锁恢复。输出中文按UTF-8读取。

## 验证

启动器的配置、迁移路径兼容、构建缓存及新增运行环境恢复测试通过。实际BAT在空临时目录环境下复用项目内运行环境成功启动；关窗立即重开的恢复结果和原业务表摘要核对见项目修改总记录第75节、证据61。

原库修改前整体备份到 `.launcher/backups/before-db-runtime-fix-20261018-102724/Data`。本轮没有新增迁移，没有修改人物卡、战斗规则或`.env`，未操作Administrator远程服务器。迁移到其他机器时一起保留`.local-database`；项目运行环境首次准备需要下载，准备完整后不依赖每日临时缓存。
