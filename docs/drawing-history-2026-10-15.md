# 画笔撤销与重做

日期：2026-10-15。基于现有画笔、整笔橡皮、房间操作事务及 Socket.IO 快照增量实现。

## 使用行为

- 地图工具和“绘画与量尺”窗口均提供“撤销”和“重做”，没有可用历史时禁用。请求进行中防止重复点击；正在落笔或擦除预览时，地图工具中的历史按钮也禁用。
- 一次连续落笔是一项操作；一次橡皮拖过多笔也是一项操作，可一键撤销、恢复整批笔画，再重做整批擦除。
- 历史按房间、地图、实际操作账号独立保存，GM 也撤销自己的操作。GM 擦除别人的笔画属于 GM 的擦除操作，可以撤销；不会撤销对方自己的绘画历史。
- 连续撤销按倒序，重做按原顺序。撤销后新建笔画或发生有效擦除会丢弃自己的重做分支；无效重复擦除、量尺操作和其他人的新笔画不会清空该分支。
- 其他成员后续修改过的笔画会跳过；批量操作中未发生冲突的笔画仍可恢复。界面提示保留他人最新状态，不通过撤销覆盖他人的后续擦除。
- 旧 STROKE 和 ERASER 仍可逐笔撤销、重做，不改写原始路径、颜色或宽度；旧像素遮罩仍沿用原来的渲染方式。量尺不进入画笔历史，原双击删除功能保持。
- 绘画权限在服务端检查，撤销和重做均要求 GM 或 draw 授权，私密地图仅 GM。撤销请求不能指定其他使用者的历史。

## 保存与同步

新增迁移 `202610150001_drawing_history`：

- `DrawingHistory` 保存 roomId、mapId、userId、APPLIED/UNDONE/DISCARDED 状态、前后变化列表和创建时间；房间或地图删除时级联清理。
- `DrawingOperation.historyId` 为可空的新列，记录当前最后修改。历史变化保存旧标记及 undone 前后值，避免撤销覆盖后来操作。
- 原数据保留，无重置、seed、表删除或几何数据回填。旧笔画在首次撤销时建立历史，沿用其原创建时间，使重做顺序保持。
- 绘画操作与现有骰子类似，使用房间行锁和 READ COMMITTED 事务，避免并发擦除、撤销和重做读取过期状态。仅单实例数据库机制，无新服务。
- 批量恢复使用一条参数化 UPDATE…FROM jsonb_to_recordset，按预期状态和修改标记过滤，避免对多笔逐条发出更新；标记和实际绘画、OperationReceipt 同事务提交。
- 原操作 ID 回执继续去重，包括同 ID 并发提交；请求失败后前端重新获取快照，恢复权威状态和按钮可用性。

操作接口仍为 `POST /api/rooms/:roomId/operations`：

| 操作 | 参数 | 结果 |
| --- | --- | --- |
| drawing.history.undo | mapId | mapId、changed、skipped |
| drawing.history.redo | mapId | mapId、changed、skipped |

复用原房间 change 广播，事件名称为上述操作名；不增加连接或逐帧数据。快照新增 `drawingHistory: [{mapId,canUndo,canRedo}]`，仅包含当前查看者在可见地图上的历史可用性，不下发其他人的历史变化列表。通过数据库分组查询汇总按钮状态。

旧 `drawing.undo` 保留量尺删除；旧客户端撤回笔画的请求也记录为可恢复的删除操作，并检查绘画和私密地图权限。
