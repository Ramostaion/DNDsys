# 普通 HTTP 访问：功能栏及头像拖动 UUID 兼容修复

## 修改原因

外网 HTTP 页面没有浏览器的安全环境待遇，`crypto.randomUUID()` 不可用。原前端在打开浮窗、提交头像位置等操作时直接调用它，因此请求尚未发到后台就报错。localhost 有特殊信任待遇；普通局域网 IP 的 HTTP 同样需要兼容。

## 实际源码修改

新增 `apps/web/src/id.ts` 中的 `createId()`：

1. 浏览器提供 `randomUUID()` 时使用原实现。
2. 缺少该方法时，使用 HTTP 环境也可用的 `crypto.getRandomValues()` 产生 16 字节随机值，再设置 UUID v4 的版本及变体位，返回原格式的 36 字符编号。[接口依据](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues)
3. 连随机字节接口也不支持时，给出更新浏览器的明确提示。

统一替换原来的 **7 个直接调用点**：操作提交、浮窗、旧攻击参考资料、导演台、私密附件、私密发送和受控分享。没有加新依赖，操作去重、服务器接口及数据库结构保持原格式；登录密钥、身份权限、访问源配置不修改。
