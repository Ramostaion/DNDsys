# 库存与编辑属性：实际回归补测

日期：2026-10-11。

## 先前覆盖与本轮补测

上一轮普通连接的 v3.0 场景验证了玩家获准后通过界面修改数值、多人同步及刷新保存，装备和背包部分主要通过接口准备与操作。上一轮真实不安全 HTTP 场景只验证窗口与地图拖动，不能据此宣称 HTTP 库存及属性界面都已测过。

本轮扩展 `apps/api/e2e/http-id.spec.ts`，同时复测 `usability-fixes.spec.ts` 内七个库存与属性场景。游戏源码没有新增修改；此次补充验证现有 UUID 兼容修改对实际业务操作的效果。

## 实际不安全 HTTP：最终 1/1（15.1 秒）

使用本机非回环 IPv4、临时端口和真实 Edge 浏览器的两份独立账号会话，确认 `isSecureContext=false`，`crypto.randomUUID` 确实不存在。未人工替换该接口。

- GM 与玩家打开／关闭窗口，GM 鼠标移动人物，玩家实时收到位置，刷新恢复。
- GM 在物品库通过界面创建饰品，编辑描述、备注及自定义数值项目；数据库保存的值逐项断言。
- 玩家通过实际拖拽将背包第 1 格物品移动至第 24 格。
- GM 在装备界面穿戴饰品，玩家法伤由 23 变为 28；穿戴后的物品离开背包格，仍保存在装备关联中。
- 玩家初始没有数值编辑框；GM 在设置界面授权后，玩家将原始法伤改为 31，最终值变为 36，GM 人物卡同步显示 36。
- GM 卸下装备，玩家法伤恢复 31；玩家刷新后仍为 31，背包仅有一件完整物品，描述、项目及备注保留。
- 实际操作回执均为标准 UUID v4，浏览器无未捕获错误。

账号、房间、地图、人物及初始背包物品的准备使用接口；物品创建与编辑、背包整理、穿脱、授权和属性编辑通过浏览器界面完成。此 HTTP 场景没有通过界面创建字段定义，也没有在 HTTP 下逐项测试全部跨角色转移。

## 普通连接：七个不同场景均通过

第一轮运行八个场景，结果 **7/8（1.5 分钟）**，七个普通连接场景通过，新增 HTTP 场景因测试定位失败。随后仅复测新增 HTTP 场景，最终通过。不同轮次不能写成一次完整 8/8。

1. 穿戴离开背包、腾格、满格卸装回滚、玩家隐藏生命上限与物品库。
2. GM 在任意角色的背包／装备间实际拖动，指定目标格与穿戴部位，保留被替换的原装备。
3. 同名属性装备加成、穿脱、物品种类及人物字段改名后的重新计算、多人同步和保存。
4. 玩家默认只读，GM 单独授权基础信息和普通数值；生命、生命上限、故事及特殊机制仍受限制，撤回权限生效。
5. 玩家背包移动及交换格子、整理失败提示与重试、过期版本拒绝、刷新恢复、物品库隐藏。
6. 自定义项目与备注保存、物品库实际拖入背包、失败重试无多余物品、旧结构化数据保留。
7. 物品创建键盘提交、创建失败后的重试，以及旧权限不重新开放玩家物品库。

## 测试过程及清理

新增 HTTP 场景先因“物品种类”的精确标签定位不匹配失败，改为限定创建表单内的下拉框；第二次因错误假定装备存储格为 -1 失败，实际为 -2。断言改为验证装备离开非负背包格，再次复测通过。这两项为测试代码修正，没有修改游戏行为。

新增测试格式检查通过。本轮未重跑单元或生产构建，上一轮 76 项单元及构建结果仅作为历史结果保留。

测试只创建并清理专属临时房间与账号，没有清空数据库、重新初始化或修改服务器访问地址。结束后核查两类测试账号和房间均为 0，原有 25 个人物保留；关闭本轮启动的测试服务。
