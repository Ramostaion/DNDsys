# 玩家授权、背包整理与地图人物信息

日期：2026-10-11。

## 实施内容

| 需求 | 已实施行为 |
| --- | --- |
| 人物卡默认不能自行修改 | 基础信息与普通字段分别授权，所有权限预设默认关闭这两项；GM 原来明确设置的授权保留。 |
| 玩家侧栏加入背包 | 新增背包图标，直接进入自己的背包；有多个角色时可选择，无角色时提示请 GM 分配。重复点击可关闭。 |
| 物品库加入背包需要授权 | 新增独立权限“从物品库加入背包”，默认关闭；加入、拖放及增加数量均在后台验证。编辑物品库不等于领取物品。 |
| 背包内自由移动格子 | 空格移动，占用格交换；原数量、备注、装备关系保留。操作失败时保留原位置，可重试；旧版本与目标格变化返回冲突提示。 |
| 生命与生命上限由 GM 修改 | 新生命字段默认 GM 编辑；已有 OWNER 生命资源与其关联上限也在后台保护，不能通过旧接口直接改血。 |
| 故事与特殊机制由 GM 修改 | 故事输入对玩家只读；剧情字段受保护；特殊机制模板仅 GM 可安装、移除或改变角色原始机制定义。 |
| 基础信息默认 GM 修改 | 名称、头像与基础信息分组字段需要独立授权；未授权时界面只读，头像上传接口也拒绝。 |
| 主地图血条和悬停基础信息 | Token 头像旁显示血条与数值；悬停显示角色、控制玩家、生命详情、基础信息、特性、技能、Buff／状态和特殊机制；自己的头像快捷栏也显示血条和概览。 |

## 权限使用

GM 打开“设置” → “房间操作权限”。可勾选全房间权限，也可在“成员例外”里将某一玩家对应权限设为“允许”或“禁止”。

人物卡基础信息、普通数值、物品库加入背包互相独立。生命、生命上限、故事和特殊机制始终由 GM 修改。授权撤回会同步到已打开的人物卡和背包。

人物卡只读不会取消角色归属，也不影响掷骰、移动自己已有的棋子或整理背包格子。NPC 仍始终由 GM 控制。其他角色物品的查看权限沿用原规则。

## 兼容与实现范围

- 没有更换架构、数据库或上传目录，没有删除人物、物品、能力或历史数据。
- 新授权保存在现有房间／成员 JSON 设置中，本次不新增数据库迁移。
- 前后台共用权限默认值和字段判定，避免界面与接口规则不一致。
- 背包换位在现有数据库事务中完成，装备关联的是物品实例，不随格子交换丢失。
- 成员授权保存期间锁定对应设置，完成同步后再保存下一项，避免连续选择覆盖前一项授权。
- 普通行动点等不关联生命上限的独立数值，在 GM 授权后仍可手动增减。
- 悬停只读取该账号已有的可见快照；隐藏 NPC 不渲染，隐藏生命上限不从默认值推测。
- 旧公式与 GM 定义的装备／能力效果继续兼容，修改权限限制的是玩家主动写入人物卡和机制定义。
