# v3.3 私密线索使用说明

## GM：写一封只给指定玩家的线索

1. 在房间左侧打开「私密线索」，进入「私密投递」。它是普通浮窗，可以与地图、人物卡、导演台和标签详情并存。
2. 填写标题，添加正文或图片；正文支持换行、列表、加粗、引用和安全链接。每条最多 5 张 JPEG / PNG / WebP 图片，单张不超过 10MB。上传显示进度；失败可重试或移除失败任务，文字和接收人不丢失。
3. 勾选接收账号。可搜索昵称或角色名、全选、清空；下方明确显示人数与昵称。收件箱属于玩家账号，一个账号的多个角色共用收件箱。
4. 点击「预览发送内容」核对正文、附件和接收人，再点击「私密发送给 N 人」。成功表示数据库已保存所有投递，离线玩家上线后也能收取；不表示对方已经阅读。
5. 「整理与分享选项」可填写 GM 私有备注、选择关联角色，或允许房间内分享副本。私有备注不发给玩家，关联角色不改变属性、任务或标签，分享默认关闭。

文字、接收人和已上传附件自动保存到当前浏览器的草稿，按账号和房间分别保存。关闭窗口或切换标签后可以继续编辑；草稿不跨设备同步。上传中关闭会提示中止上传；重新打开后可重新选择文件。浏览器存储不可用时会提示，并在关闭前确认。

### 发送时网络中断

如果出现「发送状态待确认」，表单会锁定已提交的内容。点击「确认状态并重试」：仍使用同一操作 ID，服务器已成功保存时只返回原投递，不重复发送。刷新或关闭后重新打开投递台也可继续确认。不要为同一次不确定的发送重新填写另一份草稿。

明确的输入、权限或附件错误会保留草稿并允许修改。图片文件不可用时移除附件、重新上传后再发送。

## 从剧情图库发送

在导演台选中图片，点击「发送为私密线索（选择接收人后发送）」；或在投递台点击「从剧情图库选择」。素材会复制为独立私密附件，然后仍需选择接收人并确认发送，不会自动广播或改变当前放映。

曾公开的素材会提示「此图片可能已经公开」。私密投递的地址仅限接收者读取，但无法使玩家忘记或失去已经公开过的原素材。如果图片内容本来需要隐藏，使用新的私密上传，避免先公开放映。

已导入的线索图片独立保存，删除剧情图库原素材不会删除线索附件。

## 玩家：收到、阅读与整理

- 新线索到达时只显示侧栏未读数字和短暂通知，不抢焦点、不切换地图、不自动打开图片，也不播放声音；可以点「稍后查看」。
- 打开侧栏「私密线索」进入私人收件箱。列表按时间从新到旧排列，显示标题、图片缩略图、GM、时间和未读状态；支持标题搜索、已读／未读／收藏过滤。
- 点击一条线索，打开独立阅读浮窗。详情成功显示后才提交已读；仅收到通知、悬停或打开列表不算已读。同步失败会明确提示，可点击重试。
- 可收藏／取消收藏、标记未读或已读、复制正文。每人的状态独立，其他接收者的名单与状态不会出现在玩家详情中。
- 点击图片打开独立原图浮窗，滚轮缩放、拖动平移、双击恢复适应窗口；也可点「适应窗口」或「原图 100%」。加载失败可重试，正文仍可查看；Esc 关闭当前最上层私密图片，不影响剧情放映。
- 收件箱、阅读和图片窗口都可移动、八方向调整尺寸、最小化／恢复。刷新后从收件箱重新打开历史记录；浏览器页面刷新会遵循现有窗口机制，不承诺保留打开的浮窗位置。

断线、重新登录或晚进入房间都会重新读取数据库。页面还会在重新聚焦、上线时及在线每 30 秒补拉，丢失一次实时通知不会丢失投递。被移出房间后不可读取该房间线索；角色删除不删除绑定玩家账号的历史收件。

## GM：发件箱、回执与撤回

在「GM 发件箱」查看自己发送的原件、人数与真实已读数。点击线索查看每人的阅读时间，未读不会冒充已读；玩家标记未读后统计也会更新。可按标题或显示日期搜索。

原件发送后正文与图片固定，不提供静默修改。点击「再次投递给其他成员」会把内容填回投递台，清空接收人；选择新接收人后建立新原件与新投递，不覆盖旧回执。已有草稿会先请求确认替换。

GM 可从原始投递允许／关闭后续分享，也可撤回原件及其全部分享副本。撤回后列表保留标题和撤回提示，玩家不能再次请求正文或图片。撤回不删除共享文件，不影响同一图片另行投递的其他原件，也不能消除已下载、复制或截图到外部的内容。

## 受控分享

只有 GM 开启分享权限的线索才显示「分享副本」。接收人选择本房间的其他账号，核对名单后点击「确认向 N 人分享副本」。新接收人得到独立副本与独立已读状态，只能看到自己的内容和分享者来源，不能看到原收件名单或 GM 私有备注。

GM 关闭后续分享会同时限制已有分享副本的再次分享，已经收到的内容仍能读，直到 GM 撤回。禁止跨房间分享，也不提供玩家自由私聊。

## 启动、升级与 Windows Server 保存位置

本机直接双击「启动跑团.bat」，已有启动步骤会应用添加式迁移并生成客户端。手动升级时在项目根目录运行：

```powershell
pnpm --filter @dnd/api prisma migrate deploy
pnpm --filter @dnd/api prisma generate
pnpm --filter @dnd/shared build
pnpm dev
```

迁移 `202610110002_private_clues` 只添加四张表，不清空旧人物卡、战斗、剧情素材或标签。不要执行 migrate reset。

Windows Server 的 BAT 正式启动会应用迁移并构建或复用网页/后台。附件在 `apps/api/uploads/<房间ID>/private-clues/`（自定义 UPLOAD_DIR 时使用实际目录），数据库沿用整个 `.local-database` 或原 PostgreSQL。备份须包含数据库、上传图片及配置，详见 [Windows Server 部署说明](windows-server-deployment.md)。

本轮实测覆盖本机数据库、真实 API 进程重启和浏览器恢复；Docker 镜像构建、群晖容器重建与多日运行尚未实机验证。详见 [实施状态](private-clues-implementation-status.md)。

## 四账号联机验收步骤

1. 用 GM、A、B、C 的独立浏览器会话加入同一房间，先让 C 离线；A 保持人物卡输入未提交。
2. GM 发送文字加高清图片给 A、C。检查 A 只有通知／角标，输入焦点与草稿不变；B 无通知、无收件内容，使用 A 的详情和附件地址也应被拒绝。
3. A 打开并阅读，GM 查看「2 名接收者，1 人已读」。C 上线后收件仍未读；A 的第二标签页应显示同一份投递。
4. A 收藏，刷新确认收藏仍在；模拟已读／图片请求失败，恢复网络后点击重试。
5. GM 允许分享，A 只分享给 B，确认 B 得到独立副本且无其他接收人或 GM 备注；关闭分享后 B 不能继续分享。撤回后接收端替换提示并拒绝新图片请求。
6. 在 Windows Server 的备份副本中重新启动 BAT，保留原数据库和图片，再用原账号进入，验证原件、图片、已读与收藏。目标服务器的恢复验证需实际执行，不能用本机结果替代。
