# 公开掷骰全员演出与 2 秒房间冷却

实施日期：2026-10-13。基于现有人工裁决、自由掷骰及 Socket.IO 增量实现。

## 当前使用方式

任意成员打开「骰子」，选择公开范围，输入原有骰式并提交。服务器保存有效结果后，房间内所有已连接成员的地图主视窗顶部显示掷骰者身份、当时名称、表达式和立体翻滚演出，约 1.2 秒后显示总和与计算明细。演出最多停留约 4.8 秒；下一次有效公开骰会替换它。

演出只接收服务端点数，不随机生成点数，不打开浮窗或获取焦点。浮层及子元素均不接收鼠标输入；地图与编辑窗口保留原挂载和草稿。最多绘制 6 颗轻量 CSS 骰子，大骰池的完整计算仍在历史中保存。900 像素宽的桌面视窗使用更窄的居中浮层；浏览器减少动态效果时立即显示结果，不播放翻滚。

公开骰接受后，同房间所有成员的公开按钮禁用并显示剩余秒数，骰型、数量、修正及表达式仍可预先编辑。旧人物卡的六维检定按钮也受相同冷却限制。GM 私密骰不触发顶部公开演出、不占用或改变公开冷却；原有玩家私密骰继续只给本人及 GM。

## 服务端判定与持久化

- 新迁移 `202610130001_public_dice`：`Room.publicDiceAvailableAt` 保存公开冷却截止时间；`DiceRoll.rollerName` / `rollerRole` 保存掷骰时的数据库账号名称与房间成员身份。
- 复用 `POST /api/rooms/:roomId/operations`，操作仍为 `dice.roll`，原骰式与角色关联保持。
- 仅骰子事务使用 `READ COMMITTED` 和现有的房间行 `FOR UPDATE` 锁；其他游戏操作保留原事务设置。拿锁后先查请求回执，已成功的同编号请求直接返回原结果。
- 新请求先检查公开截止时间，再计算随机数。有效骰子、操作者快照、下一次允许时间、操作回执和日志在同一事务中提交；失败整体回滚。
- 截止时间为服务端接受该有效骰子时刻加 **2000 毫秒**，不修改房间业务版本。过期请求在数据库锁等待结束后仍按最初到达时间拒绝，不会等冷却结束后自动掷骰。
- 冷却请求返回 HTTP **429**，包含 `code: DICE_COOLDOWN`、`serverNow`、`cooldownUntil`、`remainingMs`，不调用随机数，不新增骰子历史或回执。无效表达式同样不占冷却。
- 继续使用唯一操作 ID 回执去重；骰窗在网络或 5xx 回复不确定时提供「重试上次掷骰」，保留原编号和表达式。同编号并发提交也只保存及广播一次。
- 房间截止时间与骰子记录均在原数据库中；API 实例重启后从数据库恢复，无 Redis、队列或新服务。私密骰保持原有可见性，不添加公开计时提示。

旧记录的表达式、明细、时间、操作者 ID 和结果保留。迁移用当下可查的账号名称及房间成员身份回填旧记录；旧系统没有保存过去的昵称，无法追溯迁移前已更改的昵称或身份。迁移之后的新记录不随后续昵称修改而改变。

## Socket.IO 与接口变化

继续使用现有 `change` 事件，公开骰的 `event` 仍为 `dice.roll`。提交成功且非重复请求时，广播数据扩展为：

```ts
{
  operationId,
  roomId,
  roll,             // 已保存的完整记录及每颗点数、名称、身份
  serverNow,        // 服务端当前毫秒时间
  cooldownUntil     // 服务端公开截止时间
}
```

私密广播仍走原来的 GM / 发起者范围，通知只含操作编号，不广播公开演出数据。快照增加 `diceState: { serverNow, cooldownUntil }`，让刷新、晚加入和重连恢复冷却；快照不会触发历史演出。

前端只在收到公开实时事件后创建顶部演出，并按骰子记录 ID 去重。倒计时以服务端截止时间和 `performance.now()` 的经过时间计算，不依赖玩家电脑的墙上时间。倒计时更新只发生在骰子操作控件，不每 100 毫秒重画地图或人物编辑器。实时传输存在网络延迟，不承诺不同设备逐帧同时；所有人看到同一条服务器记录及点数。

历史自然语言包含时间、玩家／GM、当时名称、表达式和总和，下方展开保存的骰子与有符号修正计算。保留现有最近 100 条快照展示范围；数据库记录没有因该展示上限被删除。

## 实际测试

- 全项目类型检查、生产构建、代码与源码／联机测试格式检查通过。
- 全项目单元 **83/83**：共享 29、后台 24、网页 30。新增 7 项覆盖冷却不计算、到期边界、无效输入、私密不改变公开时间、迟到锁请求拒绝、计算与身份展示、客户端单调倒计时。
- 一轮定向浏览器回归 **6/6（1.8 分钟）**：本次公开骰、原 3D 骰盘、三账号人物卡／公式／装备／历史 Buff／人工战斗、角色标签长备注／草稿／冲突、剧情放映与私密线索离线恢复。
- 随后顶部宽窄屏尺寸与截图检查、离线错过公开骰和晚加入场景补齐，完整公开骰场景最终 **1/1（20.5 秒）**。不同轮次不加总为一次完整测试集。
- 新场景使用真实非回环 IPv4 HTTP、实际 Edge 的四份独立浏览器账号会话、两个房间。确认页面不属于安全上下文，界面提交也验证普通 HTTP 编号兼容。
- 本机原数据库已应用迁移；测试后临时账号和房间清理，原有 25 个人物保留。没有重置、初始化示例数据或覆盖服务器地址与图片。

### 失败与修正记录

开发中首次类型检查发现局部变量放在错误的回调中以及空值收窄问题，已修正。初次浏览器测试的请求注册在回环地址，而页面使用非回环地址，测试 Cookie 域不一致；改为通过同一网页源调用接口。之后测试观察器在刷新后丢失，改为每次页面加载初始化。一次通过后的测试结束曾因浏览器中断快照读取与 Prisma 断开重叠产生后台日志；补充停止接收请求及测试清理等待，最终定向回归通过。

本机第一次 BAT 自动下载 Prisma 启动组件时，最新动态组件缺少内部模块，数据库启动失败；本轮使用本机此前可用的组件启动**原数据库**，再由 BAT 应用迁移并启动应用。测试辅助命令第一次携带 `--input-type` 导致数据库工作线程报错，结束该进程后改为普通模块文件启动，后续数据库与联机测试正常。没有修改启动器、数据库内容或为产品添加该临时路径依赖。文件保存导致开发后台短暂重启时，测试启动器曾出现端口占用提示；使用已就绪的实际后台完成最终测试。

## 如何更新现有服务器

1. 关闭服务器当前运行的应用，备份原数据库、配置和图片。
2. 同步本次的 `apps/api/src`、`apps/api/prisma`、`apps/web/src` 和 `packages/shared/src`，保留服务器自己的 `apps/api/.env`、`.local-database` 和 `uploads`。此次没有新增依赖，包锁无需改动。
3. Windows BAT 现有准备流程会构建共享包、生成 Prisma 客户端、执行 `prisma migrate deploy`，随后启动应用；朋友重新刷新网页。若数据库启动组件报缺失模块，应先恢复该组件，不要初始化空库；本次未修改其自动下载逻辑。
4. 采用独立生产构建或 NAS 容器时，重新构建应用并应用上述迁移；沿用原数据库及图片卷。仅复制前端不能启用服务器冷却与姓名快照。

## 未验证与边界

- 没有执行整个浏览器测试集；未验证 Firefox、Safari、手机触屏或多日连续运行。
- 私密骰保留原行为，不新增频率限制；公开骰采用每房间独立的 2 秒冷却。历史仍使用现有最近 100 条快照 UI，没有新增全历史分页。

本次没有未完成的核心公开掷骰功能；以上事项为实际验证边界。
