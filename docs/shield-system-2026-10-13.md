# 人物护盾系统

日期：2026-10-13。

## 使用

刷新网页后，玩家与 NPC 人物卡的生命区域上方都有「护盾」。初始为 **0 / 0**。

- GM 在人物卡的「护盾」中设定护盾上限和当前护盾；点击「设定」保存，使用增减量和 − / + 手动调整。
- 玩家只查看数值。即使获准修改普通属性，仍不能自行修改护盾或上限。
- 蓝色护盾条在人物卡、地图头像旁、右上同行者角色摘要、地图/同行者悬停详情中显示，均位于生命条上方。旧人物卡也支持。
- 与现有生命字段共用原始值、最终值、来源说明、数值约束、增减记录与多人同步机制；显示比例限制在 0–100%，上限为 0 时显示空条。
- 装备数值项目「当前护盾」或「护盾上限」按既有同名属性规则联动，已有状态/特性修正通过原字段引擎计算。
- 护盾与生命独立由 GM 人工裁决调整。掷骰或战斗记录不会自动扣除资源；生命归零的背包/NPC 搜索规则仍以实际生命判断。

## 数据与兼容

护盾使用既有 `Character.fieldValues` 保存当前值与上限，使用既有 `derived` 计算最终值；复用 `character.field.set` / `character.field.adjust`、操作编号去重、版本冲突保护、活动日志与 Socket.IO 快照同步。

共享层为已有房间提供两个内置护盾字段，新建房间保存同样定义。默认标识为 `dnd_shield` / `dnd_shield_max`；如旧自定义字段已占用标识，自动选择后缀，保留原字段。重复加载不重复添加。资源类型区分生命与护盾，防止把排列在上方的护盾误当生命。

旧角色默认护盾为零，原生命/装备/备注均保留；角色复制保留护盾原始值，重算不会反复累加。没有新增数据库表、列、迁移、接口、同步事件或依赖。升级需更新共享层、API 和前端并构建，启动时按原流程重算已有角色。

- **93/93 单元**：共享 35、API 25、前端 33。包括默认/标识碰撞/重复构造、零上限与非有限值、盾和生命分离、GM 权限，以及装备/状态计算、旧卡和不重复累积。
- 全项目类型检查、生产构建、代码检查、格式检查通过。
- **最终 6/6 定向联机（1.6 分钟）**：护盾三账号场景、玩家归零拾取/NPC 搜索回归、v3.0 字段/公式/装备/Buff/人工战斗/自由骰、剧情放映保留人物卡草稿、标签私密备注/冲突/刷新恢复。
- 护盾场景实测 GM 与玩家摘要、三端地图条、悬停详情顺序和数值一致；GM 设定上限及当前值、增减、保存失败保留草稿和重试；已授权玩家直接请求仍被拒绝；装备加成、护盾归零仍保留本人背包访问、生命归零且盾未归零仍按原规则禁止本人访问；日志、复制、刷新恢复和旧卡编辑。
- 玩家截图 `.launcher/shield-player.png` 已实际查看，蓝条位于红条上方、右上摘要可读，内置标识没有显示在日常护盾区域。
- 首次定向测试错误使用「人物概览」定位实际「角色概览」，修正后单项 1/1（19.9 秒），随后最终六项全绿。途中构建发现可选上限标识的类型断言缺失、格式检查发现悬停组件格式问题，分别修复后通过。没有把失败轮次列为通过。
- 新护盾/相关易用性测试账号与房间残留均为 0，现有角色 25 个。用户原数据库、网页与 BAT 服务保留，API 按开发监视机制自动重载，未关闭用户窗口。

本轮未重跑完整浏览器套件；未验证异地/NAS 实机、触屏及全部浏览器，也未进行断电或数据库重启试验。
