# Windows Server 后台启动事务超时修复

## 问题与定位

用户在服务器更新公网访问源后，后台报 `Transaction already closed`：启动事务限制为 5000 ms，实际耗时 5035 ms。随后 Vite 代理 `/api/auth/me` 返回 `ECONNREFUSED`，是后台尚未监听或退出后的连带错误。

当前 `bootstrap.ts` 在监听前逐个人物整理历史背包位置、重算装备及人物卡属性，原来没有指定事务选项，沿用 Prisma 5 秒默认限制。仅凭服务器日志不能判断哪个查询或硬盘阶段耗时；它已明确表明事务时限过短。本次保留原人工裁决、字段、物品、权限和原数据。

## 实际改动

- `apps/api/src/bootstrap.ts`：每个人物仍单独提交或回滚，启动整理事务改为 `timeout: 30000`、`maxWait: 10000`；增加待处理人物数的启动提示。不把所有人物合并为长事务，也不全局放宽游戏操作事务。
- `apps/api/src/character-values.ts`：数值、来源、错误等完整结果没有变化时跳过重复数据库写入；结果变化时仍保存，不改变计算规则。
- `scripts/start-dnd.ps1`：后台就绪等待由 45 秒调整为 180 秒，网页等待仍为 45 秒。仍检查进程退出及真实数据库健康，不提前显示启动成功。
- 新增两项属性缓存写入回归，没有新增迁移、依赖或基础设施。

## 服务器如何应用

关闭服务器的原 BAT，将上面三个源码／启动器文件同步到服务器项目的相同位置，再双击 BAT。启动器会重新准备共享模块和数据库客户端，后台直接运行更新后的源码。

服务器原 `apps/api/.env`、`.local-database`、图片及公网访问地址保持原配置；只更新这三个文件，无需重新初始化数据库。通过独立生产包运行 API 的环境需要重新构建 API 后替换构建产物。

## 实际验证

- 全项目单元 **72/72**：共享 28、后台 19、网页 25，包含新增的两项“不重复写入／变更仍写入”检查。
- API 生产构建、代码检查通过；启动器 **18/18** 配置回归和 PowerShell 语法检查通过。
- 对现有 PGlite 实际打开旧 5 秒事务，等待 5.2 秒后查询，确认出现 `P2028` 超时；不是仅断言配置数字。
- 在真正的 `startServer` 第一个人物事务中注入 5.2 秒等待，修复后启动耗时 **5662 ms**，提交成功，真实健康接口返回 200。前后人物卡及背包／装备完整快照一致，没有清空或另建数据库。
- BAT 正常启动 25 个人物所在的原数据库，后台及 5242 网页就绪。
- 最终三账号定向浏览器回归 **1/1（16.2 秒）**，涵盖人物字段、公式、装备、历史 Buff、人工裁决与自由骰；源码格式检查通过。临时后台、网页和测试数据库结束后停止，测试数据按场景清理。

### 测试过程中的失败与复测

首次本机 BAT 数据库恢复等待超时，随后使用原数据库命令在终端启动成功，未修改或删除原数据。接着测试调度过早启动浏览器服务，与 BAT 生成客户端同时进行，触发 Windows DLL 被占用，浏览器场景失败；这次不能计为产品通过。结束竞争进程后重新启动 BAT，明确等待其就绪，再复测。最终结果记录在项目总记录中。

## 尚未验证

没有远程进入用户的 Windows Server，真实服务器冷启动速度、硬盘延迟及公网端口转发尚未实测。每个人物事务仍有 30 秒上限，BAT 后台整体等待仍有 180 秒上限；超过这些时间应结合启动日志继续定位，而不是无限延长或忽略数据错误。
