# 回合先手动态重排修复

日期：2026-10-18。

## 实际根因

检查真实代码后，没有发现 `currentTurnIndex` 保存为数据库指针；现有 `TurnSession.currentCharacterId` 已使用稳定人物 ID，参与者的 `lastActedRound` 也已记录已行动事实。

问题在调度与重算的衔接：

1. 原 `nextTurn` 完整轮末直接增加轮次并选中旧队列首位，没有自动读取有效属性重新计算。
2. `turn.total` 从 LIMIT 延长时也直接选择旧首位。
3. 中途重算虽然保留当前人物及已行动标记，但后续调度从当前数组位置向后循环查找，不能保证优先选择新排序最靠前的未行动者。例如新顺序 D→A→C→E→B，A/B已行动、C当前，结束C后原算法会先选E，正确应为D。
4. 原中途添加会重新排序全部旧成员，可能破坏GM人工顺序；同分只按ID，没有保留历史相对顺序。

本次在原回合系统内修复，没有新建第二套战斗或回合系统。

## 数据与职责

复用原结构，无数据库迁移：

- `participants` 数组顺序就是本轮锁定快照，保存本轮得分及计算依据。
- `currentCharacterId` 是当前稳定人物ID。
- `lastActedRound >= round` 相当于本轮已行动集合；新轮统一清为0。
- `firstRound` 控制本轮或下轮加入。
- `version`、操作ID回执和原房间锁保护并发。

同一人物卡多个Token仍只允许一个代表；独立NPC人物卡及人物副本分别计时，未改变参战身份规则。

| 纯函数 | 职责 |
| --- | --- |
| `calculateInitiative` | 保留原多属性加权公式、量表、个体覆盖与修正，只计算得分 |
| `sortInitiativeOrder` | 分数降序，同分保留历史顺序，无历史则按稳定ID |
| `findNextUnactedActor` | 从当前权威顺序头部查找首个本轮有效、尚未完成的人物 |
| `nextTurn` | 标记旧轮已完成并选旧轮下一位；轮末留空等待重建，绝不先选旧首位 |
| `rebuildNextRound` | 用新得分排序、增加轮数、清除已行动标记，最后从新队列选首位 |
| `recalculateTurn` | 中途手动重算，保留当前人物、首次参与和已行动记录 |
| `insertTurnParticipant` | 插入新人，已有成员相对顺序和行动事实不变 |

## 完整轮次切换

一次结束或跳过，在原事务中依次执行：

1. 验证GM、操作ID、会话版本、进行中状态、当前人物存在且本轮尚未行动，以及原400ms推进间隔。
2. 只读取当前人物的有限状态；批量递减，批量移除到期状态。
3. 通过原 `removeCharacterStates` / `refreshCharacter` 撤销属性效果。
4. 标记当前人物本轮已行动，从锁定顺序头部查找下一位未行动者。有则继续本轮，不重算其他人的先手。
5. 全部完成且达到预计总轮数，则进入LIMIT，轮次不增加，不执行下一轮重建。
6. 否则批量读取仍在队列的人物、真实装备和最新状态，调用原数值引擎计算有效属性；不依赖旧 `derived` 缓存，也不从前端获取得分。
7. 使用当前全局模板及人物独立配置计算，稳定排序生成下一轮完整队列。
8. 轮数加一，清除新轮已行动标记，按新队列选择第一位，再一次更新会话及版本。
9. 同一事务保存回执和审计。提交成功后才通过原Socket通知客户端读取经过权限过滤的完整快照。

例如 A90→B85→C70，A加速到期恢复60，本轮B/C顺序不动；C结束后下一轮为 B85→C70→A60，当前人物直接是B。

末位C身上多个状态同时到期时，先全部解除，再取真实有效属性；不会拿只解除一半的数值计算。

## 手动重算、人工排序与边界

手动重算立即更新完整排序，但不会中断当前人物或清除本轮已行动标记。例如A/B已行动、C当前，新排序D→A→C→E→B：C继续完成，然后D、E，A/B本轮不会再次行动。人工上移/下移继续保留，普通推进始终按当前保存队列选择未行动者。

新增人物单独计算，插到第一个保存得分更低的旧成员前，同分在已有同分之后；不重排旧成员。本轮立即参与者可获得本轮尚未完成的一次行动，下轮参与者在 `firstRound` 前不可被选择；不会抢占当前回合。

移出人物不扣时间、不删除人物或状态。移出当前人物时选择合法待行动者；如果本轮已完成，同样执行新轮重建。移出最后一人改为暂停等待，不能空队列无限推进；添加人物后可继续。单人物正常结算并重建下一轮。

从LIMIT延长轮数或改为不限时，也重新读取最新属性、排序并选新首位，不额外扣一次状态。暂停/继续保留当前行动；仅有下轮加入者在空等待恢复时进入其首个参与轮次。

如果模板缺失、属性非法、代表Token或地图已删除导致无法安全重建，返回明确错误并整笔回滚，旧轮、状态和请求回执都不部分保存。GM修复配置、移出失效参战人物或结束模式后再操作，不能静默使用过期得分冒充新判定。

## 并发与客户端

复用同一PrismaClient、Room `FOR NO KEY UPDATE` 短锁、READ COMMITTED、会话版本CAS及OperationReceipt。相同ID重试返回原结果，不重复扣状态；两个GM携带同版本不同ID时只有一笔推进，另一笔409并刷新权威快照。没有放宽原15s等待/10s执行上限。

批量读取参战人物及关联装备/状态，不逐人物开启事务；事务中没有Socket、HTTP或动画等待。后端通知保持最小信息，完整队列通过现有权限快照读取，隐藏人物/Token/状态及GM得分的过滤保留。

前端以整份快照更新队列、当前人物、轮次和已行动视觉状态。同会话较低版本响应被忽略；相同版本仍允许权限和实时属性变更，未变化对象继续结构共享。Socket通知只触发读取，不用其局部数据自行推进；原请求取消机制处理失效的HTTP读取。

HUD以稳定人物ID作为React Key，对队列位置播放260ms局部transform过渡，不逐帧写全局状态。新一轮的当前高亮直接来自新完整队列，不先高亮旧首位。重连以服务器快照为基线，减少动效不播放重排；动画不决定状态、得分或回合进度。
