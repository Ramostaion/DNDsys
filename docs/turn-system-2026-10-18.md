# 回合与时序系统 · 2026-10-18

## 使用方式

1. GM 从侧栏打开「先手权重配置」，新建模板，添加任意数值属性，确认每项量表上下限、百分比和缺失策略。权重必须合计 100%，也可以自动归一化；保存后点击「设为全局模板」。
2. 人物卡下方「先手属性权重」默认折叠，仅 GM 可见。默认继承全局模板，也可独立选择权重、设置额外修正、查看预估与各项贡献。「恢复全局模板」清除个体权重，保留修正值。
3. 打开「回合系统」，默认列出当前地图上真实 Token 对应的人物。选择至少一位，预计总轮数可留空，点击「进入回合模式」。同一卡的多个 Token 列一个稳定代表，优先公开 Token；独立 NPC 人物卡分别计算。
4. 全员主视窗显示有权观看的头像顺序，右上方队伍面板下显示轮数，GM 右下方可结束当前人物回合。玩家只有只读行动提示。
5. 管理窗口可暂停、继续、上下移动排序、跳过、重新计算、中途加入/移除、调整预计轮数或结束整个模式。跳过会计时；高级无耗时切换只更换焦点，原人物仍待行动，且仅可切换到本轮未行动人物。
6. 状态库可选择永久或有限持续时间；给人物分配时复制默认时间并允许修改。角色详情可独立修改剩余时间。同一状态定义在不同人物上互不影响。

本功能默认关闭，不自动启用。原战斗窗口、D20 对抗、保存记录成功弹窗、生命、技能与 Token 坐标沿用原有流程。

## 算法

`Ni = clamp((原值 - min) / (max - min) × 100, 0, 100)`

`S = Σ(Ni × 百分比 / 100) + 额外修正`

属性来自当前人物卡的数值字段，支持数值公式；旧卡来自实际数值属性和有效数值公式，不把系统合成的旧六维默认值冒充已填写属性。非数值属性、非法公式不能参与。数值均为服务器按现有状态/装备引擎重算后的有效值。

量表由 GM 明确保存，`max > min`。没有字段量表时，界面给出 0–100 初始值并提示 GM 确认，不暗中假定六维或 0–20。超界值限制到标准区间并显示警告。

默认缺失策略为阻止计算；GM 可逐项改为贡献 0 或指定缺省原值。缺失不会重分配权重，错误的非数值也不能借缺省策略通过。权重最多两位小数，服务器按万分单位检验总和；自动归一化采用稳定最大余数法，确保结果恰为 100%。最终得分保留六位小数，初次同分按稳定人物 ID，后续同分保留前一份顺序，GM 可以手动改序。

例如 0–10 量表的 8、6、7、4，分别占 40%、30%、20%、10%，得到 68。个体配置覆盖全局权重，修正值独立叠加。每轮保存计算依据，状态到期或属性调整不自动打乱本轮；全部行动后自动重算下一轮。主动重新计算会使用新属性和模板，保留当前行动者及已行动标记。

## 推进与状态时间

- 正式结束或跳过，只标记当前人物本轮已行动，并批量将其所有有限状态减一。其他人物、永久状态不变。
- 大于 1 的实例使用一次批量更新；等于 1 的实例批量删除，复用 `removeCharacterStates` 与 `refreshCharacter`，真正撤销状态数值加成和公式来源。整个操作与会话推进、回执、审计在同一事务提交。
- 从锁定顺序头部查找本轮尚未完成的人物；全部完成后，在当前事务内先移除末位到期状态、读取最新有效属性，再重算并生成新队列、增加轮数、清除新轮已行动标记，最后选新首位，不使用旧数组下标。
- 达到预计总轮数时进入 `LIMIT`，保留会话和状态。GM 延长总轮数或设为不限后进入下一轮，也可结束模式。剩余轮数为 `max(0, 总轮数 - 当前轮数)`。
- 中途加人可本轮参与或下轮参与；按保存得分插入新人，不打乱已有相对顺序。移出人物不扣减、不清除状态；移出当前人物则寻找下个待行动者，若本轮已完成则同样重建新轮。移出最后一人暂停等待，添加人物后可继续。
- 高级切换不结束原回合、不扣减状态，不为已经行动的人物创造额外正式回合。额外技能/叙事行动与本系统计时无关。
- 回合中途施加状态默认在本次正式结束时扣减；本版没有另加“从下一次自身回合开始”选项。
- 沿用同一角色/状态定义唯一的现有规则：重复添加返回冲突，批量分配跳过已有项；需要延长或覆盖时间时编辑已有实例，不自动叠加。
- 结束整个模式保留未到期状态。切换地图保持原会话绑定，新增人物只能来自该绑定地图。

## 并发、同步与权限

复用已有单个 PrismaClient、OperationReceipt 和 Socket 房间通知。GM 权限在进入事务前、取得房间锁后均验证。新系统和状态操作使用房间 `FOR NO KEY UPDATE` 作为短互斥锁，避免阻塞普通关联记录的外键检查；以 READ COMMITTED 在等待后读取新版本。会话版本 CAS、操作 ID 回执和服务器 400ms 推进间隔共同防止连击、重试和双 GM 重复扣减。客户端进行中防重；传输失败的一次自动重试复用原操作 ID 和原版本，冲突不自动改版本重做。

事务里没有 Socket、动画等待或逐状态事务，沿用原 15s 等待/10s 执行上限，没有增加超时。所有更改成功提交后才发送无人物/状态明细的房间通知；客户端读取权限快照。快照读取前后检查回合版本，发现推进穿插则限次重读，避免新顺序与旧倒计时混用；不使用覆盖整份快照的长事务。

回执与审计保留操作人、操作 ID、会话、前后版本、结束人物、状态前后时间与移除结果。GM 日志可以查看；玩家过滤全部回合/先手管理审计。GM 模板和人物权重不会进入玩家快照或普通人物操作响应。

玩家会话按绑定地图、人物及代表 Token 的现有可见性筛选；隐藏当前人物只显示等待。状态沿用 PUBLIC / OWNER / GM_ONLY，OWNER 仍使用现有控制权限。玩家不接收综合得分、计算依据、私密状态名称/ID 或 GM 模板。到期过渡同样过滤权限，仍存在的状态按当前权限检查，避免旧动画恢复已撤回信息。

断线重连仅恢复服务器会话和状态，以新快照为基线，不回放旧到期过渡，更不会执行扣减。动画只在独立 HUD 局部状态和 CSS 中运行，没有逐帧全局写入或地图坐标变化。

## 视觉与边界

HUD 使用深色半透明底和淡金色边框，头像当前行动者轻微放大、金色呼吸，已行动者变暗；头像数量增多时限制宽度、横向滚动，当前人物自动保持可见。计数器位于原队伍面板下方，右下结束按钮使用自绘 CSS 和现有图标。计时变化短暂高亮、归零图标缩小淡出；静态状态和服务端变化解耦，支持减少动态效果。

为避免多条主 HUD 冲突，当前限制每房间一个未结束会话，数据库部分唯一索引保证并发启动也不重复。单会话最多 128 位独立人物，权重最多 50 项，预计轮数和状态持续时间上限 1,000,000。地图或 Token 删除不伪造替代对象；GM 可移出缺失对象或结束会话，缺失 Token 会阻止重新计算。
