# Windows 一键启动器

入口：根目录 `启动跑团.bat`。使用步骤见 [启动顺序与玩法说明](../启动顺序与玩法说明.md)。

## 工作方式

BAT 在一个窗口中运行 `scripts/start-dnd.ps1`。启动器检查依赖、配置、单实例文件锁和 3001／5173 端口，等待数据库可查询后执行共享构建、已有迁移和客户端生成，最后启动后台与网页并打开配置中的浏览器地址。

当前 BAT 默认为正式模式，一个编译后的 Node 服务在 5242 同时提供网页、API 和 Socket.IO；没有 Vite 或源码监听器。`WEB_ORIGIN` 填实际访问源，`WEB_PORT` 设置内部监听端口。已有 HTTPS 反向代理可指向本机 5242 并启用 WebSocket。开发模式用 `启动跑团.bat -Development`，保留 API 3001 与 Vite 5242；当前完整配置见 [Windows Server 部署说明](windows-server-deployment.md)。

已经运行的数据库直接复用。未运行时，只自动启动与数据库连接端口匹配的已登记 Prisma 本地数据库，使用原有名称、数据目录和端口；不会创建示例数据、重置数据库或修改 `.env`。其他数据库需要先启动。

数据库优先使用项目内 `.local-database/prisma-dev-nodejs/Data` 中的原有登记；没有项目数据库时兼容旧的用户目录。用户目录优先使用 `LOCALAPPDATA`，并回退检查 Windows 系统提供的本地用户目录。找到登记后，启动器让后续数据库命令使用同一目录，避免检查与实际启动指向不同的数据位置。项目数据库登记损坏时直接报告错误，不会悄悄切回旧备份。启动窗口会显示实际目录。本地登记缺失、损坏或端口不匹配时会显示具体原因。登记文件带有 UTF-8 BOM 时也能读取。

每个启动命令在运行前加入 Windows Job Object；它创建的后续子进程也归属同一个 Job。启动器退出或窗口关闭时，系统关闭 Job 句柄，结束这些进程。无需常驻清理服务，也不会按程序名称批量结束其他 Node.js 进程。浏览器由窗口外部打开，不属于需要结束的服务器进程。

本地数据库端口开始监听不代表已经能查询，因此启动迁移前会执行只读 `SELECT 1` 检查。异常关窗留下的短暂锁由数据库 CLI 恢复，启动器等待并重试，不手动删除数据库文件或锁目录。
