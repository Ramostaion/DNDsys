# Windows Server：复制原项目并一键启动

更新日期：2026-10-14。适用于 Windows Server、Ryzen 5 5600G、32GB 内存。默认正式运行，网页/API/Socket.IO 共用 **5242**。

最新实际运行、重启、联机和资源体积验证见 [本轮性能调整与验证](windows-server-performance-2026-10-14.md)。下方最后一节保留先前复制与环境安装的测试原记录。

## 1. 在原电脑准备复制

先保存游戏内容，关闭「启动跑团」窗口，等服务停止后再压缩或复制整个 `projectDND` 文件夹。复制进行时不要再次启动数据库。

以下内容必须带上：

| 内容 | 用途 |
| --- | --- |
| 项目源码、`scripts`、`启动跑团.bat`、包配置和锁文件 | 启动程序及补装依赖 |
| **整个 `.local-database` 文件夹** | 当前房间、账号、人物卡、背包、线索及数据库登记信息 |
| `apps/api/.env` | 原数据库连接、登录密钥和配置 |
| `apps/api/uploads` | 原图片；如改过 `UPLOAD_DIR`，同时复制其实际目录并修正路径 |

不要只复制 `.pglite` 或仅复制网页构建目录。复制前在资源管理器中开启“隐藏的项目”，确认配置和隐藏目录都在。

`node_modules` 可以省略，启动器会按锁文件重新安装。项目内 `.launcher/runtime` 可一起复制，里面有本次实测下载的 Node.js 和 pnpm，可省去它们的再次下载；项目依赖是否需要补装仍取决于复制完整性、目录和服务器环境。开发机的 Codex 和用户缓存不是启动必需项。

## 2. 在服务器修改访问地址

放到服务器的可写目录，例如 `D:\projectDND`。编辑**服务器这份** `apps/api/.env`，设置：

```dotenv
WEB_PORT=5242
WEB_ORIGIN=http://你的实际服务器地址:5242
```

将“你的实际服务器地址”替换成朋友真正使用的服务器 IP 或域名。所有人使用同一个地址访问。只在服务器本机测试时可保留 `http://localhost:5242`；朋友无法用自己的 localhost 连接你的服务器。

保留原 `DATABASE_URL` 和 `JWT_SECRET`。现有本地库连接仍为 `127.0.0.1:51214`，数据库随项目启动，无需转换数据库。`.env` 中 `PORT=3001` 保留给开发模式；正式启动器在自己的子进程中使用 `WEB_PORT=5242`，不改写原配置文件。当前默认图片目录 `./uploads` 相对于 `apps/api`。

服务器网页监听所有网卡。要从异地访问，还需让 Windows 防火墙及云服务器入口或路由器允许 TCP **5242**；启动器不会自动修改防火墙或公网转发。玩家只需网页入口，不需要数据库端口。已有 HTTPS 反向代理时，`WEB_ORIGIN` 填实际 HTTPS 访问源，代理到本机 5242 并启用 WebSocket；网页实际监听端口仍由 `WEB_PORT` 决定。

## 3. 双击启动

在服务器双击 `启动跑团.bat`，首次准备可能需要几分钟。

启动器依次执行：

1. 检查原配置及重复启动窗口。
2. 使用已有 Node.js 24；没有兼容版本时从官网下载 Node.js **24.18.0** 到项目内并检查 SHA256，不要求全局安装。
3. 检查项目指定的 pnpm **11.25.0**；缺少时使用 npm 安装到项目内。
4. 检查依赖、复制后的链接和图片处理模块。缺失或环境改变时，按原锁文件自动安装／修复。
5. 识别项目内原数据库，备份并修正复制前的日志绝对路径，再启动已有数据库。缺少数据库内容时直接提示复制不完整，不创建空库。
6. 生成数据库客户端、等待实际查询成功、应用已有迁移；首次启动/源码或运行环境变化时构建整个项目并预压缩网页资源，未变化则复用构建。
7. 在正式模式运行编译后的后台，5242 同时提供网页、API 和 Socket.IO；不启动 Vite/源码监听器。

**不会执行示例初始化或数据库重置。原测试账号和房间继续使用。**

环境检查和下载通常无需管理员权限；项目目录必须可写。使用 64 位且支持 Node.js 24 的 Windows；Node 官方列出 Windows Server 2016 起的 x64 支持范围，也要求系统处于受支持状态，部署建议使用仍受微软维护的服务器版本。[Node 平台要求](https://github.com/nodejs/node/blob/v24.x/BUILDING.md)

首次补装需要能访问 `nodejs.org`、`registry.npmjs.org` 以及 Prisma 安装过程使用的下载站点。失败后保留提示，恢复网络后重新双击；已完成的环境安装会复用。网络不通时不保证自动下载成功。

正常启动后浏览器打开配置的地址。保持启动窗口打开；玩完保存，再点窗口右上角 **X**，本次启动的网页、后台及本地数据库一起停止。原先已独立运行的数据库会保留。

这是窗口管理的启动方式：服务器注销、重启后需重新双击 BAT，目前没有注册 Windows 服务或开机自启。远程桌面断开与注销不同，能否保留登录会话取决于服务器会话策略。

## 4. 5600G / 32GB 的运行配置

以下默认值不要求填写，可在服务器自己的 `apps/api/.env` 覆盖：

```dotenv
DND_RUN_MODE=production
DND_NODE_HEAP_MB=4096
DND_WORKER_THREADS=8
DND_IMAGE_THREADS=2
DND_IMAGE_CACHE_MB=128
```

| 参数 | 用途 |
| --- | --- |
| 4096MB Node 堆上限 | 按需增长，不预先占用 4GB；给图片、数据库和操作系统留余量 |
| 8 个后台线程 | 文件和图片等异步任务使用；只作用于正式应用进程，数据库启动不改变 |
| 每个图片任务 2 线程、128MB 缓存 | 控制多个图片处理任务的 CPU 和内存竞争，图片大小/像素上限保留 |
| Brotli/gzip 预压缩 | 构建时生成，请求时读取压缩文件，降低传输字节数 |
| 哈希资源一年缓存、HTML 不缓存 | 更新版本时入口立即读取，已有带哈希 JS/CSS 可复用 |
| 65 秒 HTTP 保活 | 请求复用连接；停止时等待已接收请求完成并释放空闲连接 |

这些是适合本项目小范围使用的可调整初始参数，不代表已对你的实际服务器完成性能跑分。原有 `NODE_OPTIONS` 已指定堆上限时优先保留。

修改代码时可使用 `启动跑团.bat -Development`（3001 API + 5242 Vite），或直接运行 `pnpm dev`。正式模式需停止旧窗口再重启才能加载新后端/网页；启动器会检测源码及构建文件变化，缺失/被修改的构建会重新生成。

## 5. 出错时查看哪里

外网 HTTP 操作出现 `crypto.randomUUID is not a function` 时，见 [HTTP 浏览器兼容修复与同步步骤](http-browser-uuid-2026-10-11.md)，同步更新后的前端源码并刷新网页。

若出现 `Transaction already closed` 且提示 5000 ms，见 [启动事务超时修复](startup-transaction-timeout-2026-10-11.md)：同步三个修复文件后重启，保留服务器原配置、数据库和图片。

- 错误窗口显示失败环节；同一项目只保留一个启动窗口。
- `.launcher/last-startup.json` 保存最近启动阶段、路径和错误，便于排查，不保存数据库连接密码。
- 端口占用会停止本次启动，不会强制关闭占用者。
- 数据库路径自动修复前，在相应 `server.json` 旁保存 `server.json.before-relocation`；仅修改已识别的旧日志路径。
- 图片缺失时先检查是否带齐原上传目录；账号或房间不符时先确认是否使用了原配置及整个 `.local-database`，不要重新初始化。

备份时同样先关闭启动窗口，保存 `.local-database`、配置及图片目录。游戏过程中复制数据库文件不作为可靠备份方式。
