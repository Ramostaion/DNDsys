# 《万象跑团》先手算法说明

更新日期：2026-10-18。本文依据当前项目实际实现编写。

## 1. 先手值决定什么

先手值用于排列回合系统中的人物行动顺序：**分数越高，默认越先行动**。

当前采用确定性算法，相同的属性、量表、权重和修正值会得到相同结果，不额外投掷 D20。原战斗窗口的属性对敏捷 D20 判定仍使用原规则，与这里的先手排序分别计算。

## 2. 计算公式

每项属性先换算成 0–100 的标准值：

```text
标准值 Ni = 限制到 0–100 范围内〔(当前有效属性值 Xi − 量表下限 Li) ÷ (量表上限 Ui − Li) × 100〕
```

然后按照权重合计，并加上 GM 设置的人物修正：

```text
单项贡献 Ci = 标准值 Ni × 权重百分比 Pi ÷ 100

综合先手值 S = 所有单项贡献之和 + 额外先手修正 B
```

| 符号 | 含义 |
| --- | --- |
| Xi | 人物当前有效的属性值，包含现有数值引擎计算的装备、状态等修正 |
| Li / Ui | GM 为这项属性指定的量表下限 / 上限，必须满足上限大于下限 |
| Ni | 属性换算后的标准值，范围为 0–100 |
| Pi | 此属性所占百分比，例如 40 表示 40% |
| Ci | 此属性为综合先手提供的分数 |
| B | 人物额外修正，默认 0，可正可负 |
| S | 最终用于排序的综合先手值 |

所有属性的权重合计必须为 **100%**。单项标准值限制在 0–100，但叠加额外修正后的最终先手值不再限制在这个区间，因此可以小于 0 或大于 100。

## 3. 完整计算示例

假设 GM 选择四项属性，量表都为 0–10：

| 属性 | 当前有效值 | 量表 | 标准值 | 权重 | 得分贡献 |
| --- | ---: | --- | ---: | ---: | ---: |
| 敏捷 | 8 | 0–10 | 80 | 40% | 32 |
| 感知 | 6 | 0–10 | 60 | 30% | 18 |
| 智力 | 7 | 0–10 | 70 | 20% | 14 |
| 力量 | 4 | 0–10 | 40 | 10% | 4 |
| 合计 | — | — | — | 100% | 68 |

没有额外修正时：

```text
S = 80 × 0.4 + 60 × 0.3 + 70 × 0.2 + 40 × 0.1
  = 32 + 18 + 14 + 4
  = 68
```

如果 GM 为此人物设置额外修正 +2，最终先手为 **70**；设置 −1，则为 **67**。

这里的属性与比例仅用于举例。项目支持人物卡中的其他合法数值属性，不固定为这四项或传统六维。

## 4. 不同量表如何比较

不同属性可以使用不同的数值范围。它们必须先换算为标准值，再参与加权，不能直接把原始数值混合相加。

以下配置仍会得到与上例相同的 68 分：

| 属性 | 当前有效值 | 量表 | 标准值 | 权重 | 得分贡献 |
| --- | ---: | --- | ---: | ---: | ---: |
| 敏捷 | 8 | 0–10 | 80 | 40% | 32 |
| 感知 | 60 | 0–100 | 60 | 30% | 18 |
| 智力 | 14 | 0–20 | 70 | 20% | 14 |
| 力量 | 400 | 0–1000 | 40 | 10% | 4 |

量表也可以有非零或负数下限。例如，量表为 −10 至 10，属性值为 0：

```text
N = (0 − (−10)) ÷ (10 − (−10)) × 100 = 50
```

需要注意：

- 量表是 GM 保存的规则，不是当前参战人物中的最低值和最高值。换一批人物不会自动改变量表。
- 超过量表上限时标准值按 100 计算，低于下限时按 0 计算，并在明细中提示超界。
- 属性越大，标准值越高。当前没有“原值越小越先行动”的独立反向选项。
- 添加属性时，界面优先使用字段已有的上下限；未提供边界时，相应边界使用 0 / 100 的初始值，需要 GM 确认。
- 同一种规则下需要公平比较时，应为参与比较的人物使用一致的属性量表；个体自定义配置的依据可在明细中审核。

## 5. 哪些属性可以参与

自定义人物卡读取房间字段定义中类型为“数值”的属性，包括数值公式字段。旧版人物卡读取实际存在的数值属性，以及已有有效数值结果的公式。

正式计算前，服务器通过现有引擎重新计算人物的有效属性值，因此已生效的装备、状态、特性等数值修正会按原有规则反映到先手值中。

文字、布尔值、无效数字、计算失败的公式不能作为数值使用。字段名称可以自定义，系统通过稳定字段标识关联；旧卡没有实际填写的属性，不会仅因为系统存在某个默认六维数值就自动视为已拥有。

自定义卡没有填写某项属性，但该字段有有效数值默认值时，沿用人物卡的默认值。没有可用值时，再执行该项属性配置的缺失策略。

## 6. 缺失属性如何处理

每项参与属性可以单独设置一种策略：

| 策略 | 实际处理 | 适用情况 |
| --- | --- | --- |
| 阻止计算（默认） | 此人物先手无效，提示缺少哪项属性 | 要求人物资料完整 |
| 贡献为 0 | 该项得分直接为 0，其他项保持原权重 | 允许缺项且不提供该项收益 |
| 指定原值 | 使用 GM 填写的缺省原值，按该项量表正常换算 | GM 明确规定统一缺省值 |

沿用第 3 节示例，如果人物缺少占 40% 的敏捷，其余三项贡献仍为 18、14、4：

```text
阻止计算：没有有效先手结果，需先补值或调整策略。

贡献为 0：S = 0 + 18 + 14 + 4 = 36。

指定原值 5，敏捷量表为 0–10：
敏捷标准值 = 50，贡献 = 50 × 40% = 20。
S = 20 + 18 + 14 + 4 = 56。
```

**缺少属性不会自动把它的权重分给其他属性。**“贡献为 0”也不等于“把原值设成 0 后再换算”：对于 −10 至 10 的量表，原值 0 对应标准值 50，但缺失策略“贡献为 0”仍然直接贡献 0 分。

这些策略处理的是缺失值。实际填入的非数值内容、公式计算错误，以及已经删除或不合法的字段，不会通过缺省策略自动绕过校验。即使某项权重设为 0，只要仍保留在配置中，也需要通过该项校验；完全不参与时应移除该项。

## 7. 权重自动归一化

“权重自动归一化”按当前各项权重的比例，将总和调整为 100%。它调整的是百分比，与第 4 节的属性量表换算是两个步骤。

例如输入 4、3、2、1，自动调整为 40%、30%、20%、10%。

系统使用最大余数法保留两位小数，确保最终总和恰好为 100%：

1. 按各项比例分配 10,000 个单位，每单位表示 0.01%。
2. 每项先取整数部分。
3. 将剩余单位优先补给小数余数最大的项；余数相同时按配置中的原顺序处理。

三项相同权重的结果为 **33.34%、33.33%、33.33%**。全部权重都为 0 时无法自动归一化，需要先给至少一项正权重。

## 8. 全局模板与人物配置

权重来源按以下优先级选择：

```text
人物有个体自定义权重 → 使用整套个体权重。
人物没有个体自定义权重 → 使用房间当前选中的全局模板。
两者都没有 → 提示尚未配置，不能得到有效先手结果。
```

个体权重整套覆盖全局权重，不是只替换其中几项。人物额外修正 B 在两种模式下都独立生效，默认 0。

GM 可以保存多套全局模板，但一个房间当前只选择一套。“恢复全局模板”会清除该人物的个体权重，**保留当前设置的额外修正值**。如果也要取消修正，需要将修正值改为 0 并保存。

配置和修改由 GM 管理。GM 可以查看每项原值、量表、标准值、权重、贡献、警告和最终结果；玩家 HUD 不返回 GM 的权重配置、综合得分或计算依据。

## 9. 排序、同分与计算时机

### 进入回合模式

服务器读取所选人物当前属性与配置，计算得分，按以下规则建立顺序：

1. 综合先手值从高到低。
2. 初次得分相同，按稳定人物 ID 排序；后续重算同分优先保留上一份队列的相对顺序。
3. GM 可在管理窗口使用上移、下移人工调整。

相同人物卡的多个 Token 只使用一个代表，避免人物重复入队；独立 NPC 人物卡或人物副本按各自 ID 分别计算。同分规则不使用人物名称、客户端随机数或额外 D20。

### 回合已经开始

每一轮保存当时的得分、计算明细和顺序。本轮属性、装备和状态变化立即影响有效数值，但不会自动打乱本轮已确定的队列。

所有本轮人物完成后，服务器先结算最后一人的状态，移除到期效果，再读取最新有效属性和配置，重新计算下一轮先手、排序，最后从新队列选出第一位人物。整个过程在同一事务保存。例如第1轮 A90→B85→C70，A的加速到期变为60，则第2轮直接从 B85→C70→A60 中的B开始。

GM中途点击“重新计算先手”会立即更新排序，但当前人物继续完成自己的回合，已行动者本轮不能再次行动。当前人物结束后，从新排序头部选择首位未行动者，不能按旧数组位置继续往后走。人工上移/下移仍可用。

切换全局模板、修改个体配置或额外修正，在下一轮重建时使用；若需本轮生效则主动重算。中途加入只计算新人，插入到首个保存得分更低的成员前，同分排在已有同分之后；其他成员相对顺序、当前人物和已行动记录不变。本轮或下轮参与仍由GM选择。

达到预计轮数上限时停在原轮次，不创建下一轮；GM延长后才按最新属性重建。移出最后一人会暂停等待添加人物，不清除人物卡或状态。详见[动态排序修复说明](turn-round-rebuild-2026-10-18.md)。

## 10. 精度与校验范围

| 项目 | 当前规则 |
| --- | --- |
| 参与属性数量 | 1–50 项，不能重复 |
| 单项权重 | 0–100%，最多两位小数 |
| 权重总和 | 必须为 100%，按 0.01% 单位校验 |
| 量表 | 上限必须大于下限；上下限各在 −10¹² 至 10¹² 内 |
| 指定缺省原值 | 有限数值，范围 −10¹² 至 10¹² |
| 人物额外修正 | 有限数值，范围 −1,000,000 至 1,000,000 |
| 最终得分 | 四舍五入到六位小数后用于排序，不额外限制在 0–100 |
| 界面明细 | 标准值和贡献显示两位小数，计算不会使用这些显示值重新求和 |

因此，明细表经过显示舍入后逐项手算，可能与最终得分存在很小差异；以服务器保存的最终得分为准。

## 11. GM 配置步骤

1. 打开侧栏“先手权重配置”，选择新建模板并填写名称。
2. 添加参与的数值属性，为每项确认量表上下限、权重及缺失策略。
3. 确认总权重为 100%，或使用“权重自动归一化”。
4. 保存模板，并点击“设为全局模板”。
5. 如需特殊人物规则，在人物卡“先手属性权重”中设置个体覆盖或额外修正并保存。
6. 打开“回合系统”，查看候选人物的先手预估和计算明细，选择人物进入回合模式。
